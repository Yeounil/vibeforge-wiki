# 확장성

시스템에 가해지는 부하(트래픽·데이터·연산)가 증가했을 때 성능 저하 없이 리소스를 유연하게 늘릴 수 있는 능력.

## 인스턴스 (Instance)

클라우드(AWS, GCP 등)에서 물리 서버를 가상화 기술로 쪼개어 만든 독립적인 가상 컴퓨터. 자신만의 CPU·RAM·OS를 갖는다. 분산 시스템은 이 인스턴스 수십~수백 대가 네트워크로 연결된 구조.

## 수직 확장 (Vertical Scaling / Scale-up)

단일 인스턴스의 **스펙(CPU·RAM·디스크)을 업그레이드**. "슈퍼맨 한 명 고용".

| 장점 | 단점 |
|------|------|
| 구조 단순, 코드 변경 불필요 | 물리적 한계(천장 존재) |
| 데이터 일관성 자동 보장 | 비용 비선형(성능 2배 = 비용 4~8배) |
| | SPOF — 죽으면 전체 마비 |
| | 업그레이드 시 다운타임 발생 |

## 수평 확장 (Horizontal Scaling / Scale-out)

인스턴스 **개수를 늘려** 부하를 분산. "평범한 직원 100명 고용".

| 장점 | 단점 |
|------|------|
| 사실상 무한 확장 가능 | 로드 밸런서 필수 |
| 높은 [[가용성]]·[[장애 허용성]] | 무상태(Stateless) 재설계 필요 |
| 무중단 확장 | 데이터 일관성 딜레마 |
| 범용 하드웨어로 비용 효율 | 아키텍처 복잡도 급증 |

## 실무 패턴

- **앱 서버**: 무상태(Stateless) + 수평 확장 기본
- **메인 DB**: 수직 확장 우선 → 한계 도달 시 Replication·Sharding으로 수평 확장
