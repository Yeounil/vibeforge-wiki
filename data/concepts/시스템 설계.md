# 시스템 설계

소프트웨어 시스템의 아키텍처·컴포넌트·모듈·인터페이스·상호작용을 정의하여 기능적·비기능적 요구사항을 충족하는 과정.

## 6단계 프로세스

1. **요구사항 분석** — 기능적·비기능적 요건, 데이터 조회·저장 패턴 파악
2. **상위 수준 아키텍처 설계** — 전체 구조·컴포넌트·모듈·인터페이스 정의
3. **하위 수준 상세 설계** — 알고리즘·컴포넌트 간 상호작용 설계
4. **UI 설계** — API로 백엔드와 통신할 사용자 인터페이스 정의
5. **API 설계** — 프론트엔드↔백엔드 통신 인터페이스
6. **DB 설계** — 데이터 구조·저장 메커니즘 (RDBMS / NoSQL 등)

## 상위 수준 설계 — 아키텍처 패턴

| 패턴 | 설명 |
|------|------|
| 모놀리식 | 모든 컴포넌트를 결합한 단일 애플리케이션 |
| 클라이언트-서버 | 클라이언트가 하나 이상의 서버에 서비스 요청 |
| 마이크로서비스 | 네트워크로 통신하는 작고 독립적인 다수 서비스 |
| 이벤트 주도 | 비동기 이벤트·메시지로 컴포넌트 상호작용 |

상위 설계 시 고려 축: [[확장성]], [[가용성]], 유지 보수성, 지연 시간

## 하위 수준 설계 — API 하위 호환성

- URI 경로 또는 헤더 기반 **버전 관리(Versioning)**
- **추가(Additive) 원칙**: 기존 필드 삭제·수정 대신 새 필드만 추가
- **어댑터 패턴**: 구형 요청 → 최신 로직 → 구형 응답 변환
- **점진적 일몰(Deprecation Policy)**: 트래픽 모니터링 후 구형 버전 종료

## 코드 최적화 기법

- 리팩터링 / 루프 언롤링 / 메모이제이션 / 병렬 처리
