# 3단계 스키마

[[데이터베이스]]를 **사용자·조직·저장 장치** 세 관점에서 각각 정의한 스키마 계층. 각 단계는 독립적이며 매핑으로 연결되어 [[데이터 독립성]]을 가능케 함.

## 세 단계

| 단계 | 관점 | 설명 |
|---|---|---|
| **외부 스키마** (External / Subschema) | 사용자·응용 | 전체 DB의 **논리적 일부분**. 부서별·업무별 뷰. |
| **개념 스키마** (Conceptual / Schema) | 범조직 | 모든 외부 스키마의 **통합**. DB 전체의 논리 구조. |
| **내부 스키마** (Internal) | 저장장치 | 물리적 저장 구조·접근 방법. |

## 예시 (학사 시스템)

| 외부 스키마 | |
|---|---|
| 학생과 | 학번, 성적 |
| 교무과 | 학번, 이름 |
| 학적과 | 학번, 주소 |

→ **개념 스키마**: `학번, 이름, 성적, 주소`
→ **내부 스키마**: `학번(10자), 이름(5자), 성적(정수), 주소(50자)`

## 스키마 정의 요소

- **개체(Entity)** — 데이터 구조의 기본 단위
- **속성(Attribute)** — 개체를 구성하는 값
- **관계(Relationship)** — 개체 간 연관
- **제약 조건** — 유효한 상태를 규정

## 데이터 사전 · 메타 데이터

각 단계 스키마는 **데이터 사전(Data Dictionary)** 이라는 시스템 DB에 저장. 저장된 "데이터에 관한 데이터"가 **메타 데이터(Meta Data)**.

## 역할

단계 간 **매핑(Mapping)** 이 [[데이터 독립성]]의 구현 기반.
