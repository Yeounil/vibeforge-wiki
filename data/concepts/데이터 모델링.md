# 데이터 모델링

복잡한 현실 세계를 일정한 표기법으로 **추상화 · 단순화 · 명확화**하여 데이터베이스로 구축 가능한 구조로 변환하는 과정. 정보 공학(Information Engineering) 기반.

## 3중 세계관

| 세계 | 대응 | 변환 |
|---|---|---|
| 실세계 | 개체(Entity) — 사람·장소·사건·개념 | |
| 개념 세계 | 개체 타입 | ← **추상화** |
| 컴퓨터 세계 | 레코드(튜플) — 논리적 구조 | ← **모델링** |

## 모델링 관점 2축

- **데이터 관점 (What)** — 어떤 데이터·데이터 간 관계
- **프로세스 관점 (How)** — 업무가 하는 일
- **상관 관점 (Interaction)** — 프로세스가 데이터에 미치는 영향

정보 공학 = 데이터·프로세스 **분리**. 객체 지향 = **동시** 모델링.

## 3단계 모델링

| 단계 | 특징 | 산출물 | 프로젝트 단계 |
|---|---|---|---|
| **개념 데이터 모델링** | 추상화 수준 높음, 핵심 개체·관계 도출 | [[ER 다이어그램]] | 계획/분석 |
| **논리 데이터 모델링** | 개념 모델 상세화, 속성·식별자, **정규화** | 정규화된 [[릴레이션]] 스키마 | 분석 |
| **물리 데이터 모델링** | 대상 DBMS 고려, 데이터 타입·크기, **인덱스·역정규화** | 물리 스키마 | 설계 |

**개념 모델 ≠ 개괄·추상 모델.** 주요 개체·식별자·관계가 모두 도출된 **구체적** 모델.

## 데이터 모델의 중요성

- **파급효과** — 구축 중 구조 변경은 전체 프로젝트의 위험 요소.
- **간결한 표현** — 수백 페이지의 기능 요구보다 데이터 모델 리뷰가 빠름.
- **데이터 품질** — 데이터는 기업 자산. 오래될수록 가치 상승.

## 유의점

- **중복(Duplication)** — 사용자·시간·장소 파악 어려움.
- **비유연성(Inflexibility)** — 데이터 정의와 사용 프로세스를 분리해야 함.
- **비일관성(Inconsistency)** — 중복 없어도 발생. 데이터 간 연관 정의로 예방.

## 좋은 데이터 모델 조건

완전성 · 중복 배제 · 데이터 재사용 · 업무 규칙 반영 · 안정성·확장성 · 간결성 · 의사소통 · 통합성.
