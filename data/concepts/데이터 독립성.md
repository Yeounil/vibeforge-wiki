# 데이터 독립성

데이터의 **논리적·물리적 구조가 변경되어도 응용 프로그램이 영향받지 않는** 성질. [[DBMS]]의 궁극적 목적.

## 두 가지 독립성

- **논리적 독립성** — 논리 스키마(개념 스키마) 변경이 외부 스키마·응용에 영향 없음.
  - "내용에 의한 참조"를 통해 구현 (위치가 아닌 값으로 접근).
- **물리적 독립성** — 물리 구조(디스크 → SSD, 인덱스 추가 등) 변경이 논리 구조·응용에 영향 없음.

## 예시

같은 논리 구조 `[[김장수, 3.5, 4학년], [이정화, 3.1, 1학년]]` 이 어떤 응용 관점에서는 `<학번, 4학년, 3.5>` 순서로 보여도 무방해야 함. 저장 장치가 디스크에서 SSD로 바뀌어도 응용은 그대로.

## 대조: 데이터 종속성

파일 시스템의 고질 문제. 파일 구조가 바뀌면 **모든 응용 프로그램을 재작성**해야 함. 위치에 의한 참조 때문.

## 구현 기반

[[3단계 스키마]] 간의 **매핑(Mapping)** 이 논리/물리 독립성을 가능하게 함.
