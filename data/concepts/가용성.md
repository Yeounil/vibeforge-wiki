# 가용성

분산 시스템이 장애·예기치 않은 상황 속에서도 지속적으로 정상적인 서비스를 제공하고 응답할 수 있는 능력. [[CAP 정리]]의 A.

$$\text{Availability} = \frac{\text{Uptime}}{\text{Uptime} + \text{Downtime}}$$

## 측정: Nines

| 수준 | 가용성 | 연간 다운타임 |
|------|--------|--------------|
| 쓰리 나인 | 99.9% | ~8시간 45분 |
| 포 나인 | 99.99% | ~52분 |
| 파이브 나인 | 99.999% | ~5분 |

## 보장 방식

1. **SPOF 제거 + 다중화(Redundancy)**
   - **Active-Active**: 여러 노드 동시 요청 처리 → 즉각 전환
   - **Active-Passive**: 주 서버 장애 시 대기 서버 역할 인계

2. **로드 밸런싱**: 트래픽 분산 + 장애 노드 자동 차단

3. **Heartbeat & Failover**: 주기적 생존 신호 → 미응답 노드 격리, 자동 복구

4. **데이터 복제**: 다중 노드에 데이터 유지. Raft·Paxos 등 분산 합의 알고리즘

5. **무상태(Stateless) 아키텍처**: 세션을 Redis 등 외부 저장소에 분리 → 노드 교체 자유

## 가용성 vs 신뢰성

- **가용성**: "지금 당장 응답하는가?" (상태의 단면)
- **신뢰성**: "얼마나 오래 안 뻗는가?" (시간의 연속성) → [[신뢰성]] 참조

예: 1시간마다 1초 크래시 → 가용성 99.97%(높음), 신뢰성 낮음
