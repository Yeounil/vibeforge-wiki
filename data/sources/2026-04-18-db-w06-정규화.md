# DB 6주차 — 정규화 (1NF → BCNF)

DB 강의 (2026 봄학기)의 6주차. ⑪ 이상 상태와 제1·2정규형, ⑫ 제3정규형·BCNF·기타.

## 강의 11 — 정규화와 1NF·2NF

### 1. 이상 상태 (Anomaly)

릴레이션 속성 그룹핑이 잘못되면 발생하는 부작용. 3종류:

| 이상 | 예 |
|---|---|
| **삽입 이상 (Insert)** | 400번 학생이 2학년이란 사실을 과목 등록 없이 삽입 불가 — 원하지 않는 정보의 강제 삽입. |
| **삭제 이상 (Delete)** | 200번 학생이 과목 취소 시 "3학년" 정보도 함께 삭제 — 연쇄 삭제로 정보 손실. |
| **갱신 이상 (Update)** | 300번 학생 학년 변경 시 관련 튜플 모두 수정 필요 — 일부 누락 시 비일관성. |

원인: **한 릴레이션이 여러 개체 정보를 혼재** → 속성 간 연관성 중복.

### 2. 좋은 릴레이션 가이드라인 5

1. 한 튜플 = **한 개체(또는 관계 인스턴스)**
2. 서로 다른 개체 속성이 섞이면 안 됨
3. 외래키로 다른 개체 참조
4. 개체와 관계는 **분리**
5. 한 튜플이 여러 개체 = 중복 → 이상 상태

### 3. [[정규화]] (Normalization)

속성들의 여러 연관 관계를 **분해하여 별개의 릴레이션**으로. 하나의 연관 관계는 하나의 릴레이션에서만 나타나도록 설계.

### 4. 정규화의 3원칙

1. **정보 표현의 무손실** — 스키마 변환 후에도 원본 정보 전부 보존.
2. **최소의 데이터 중복**.
3. **분리의 원칙** — 독립 관계성은 별도 릴레이션.

### 5. 무손실 분해 (Lossless Decomposition)

릴레이션 `R = R1 ∪ R2` 로 분해 후 자연 조인으로 **복구 가능**해야 함. 거짓 튜플이 발생하면 손실 분해.

`R(A, B, C)`에서 함수 종속 `B → C` 존재 시:
- `R1(A, B)` + `R2(B, C)` 로 분해 → **무손실** (조건: `R1 ∩ R2 → R2 − R1`).

### 6. 제1정규형 (1NF)

모든 속성의 도메인이 **원자값(Atomic)** 으로만 구성된 릴레이션. 관계형의 모든 릴레이션은 자동으로 1NF.

### 7. [[함수적 종속성]] (Functional Dependency, FD)

어떤 릴레이션 R에서 **속성 X의 값에 대하여 속성 Y의 값이 하나만** 연관될 때 `X → Y`.

- **X** = 결정자(Determinant), **Y** = 종속자(Dependent).
- X가 키이면 R의 모든 속성 Y에 대해 `X → Y` 성립.
- X가 꼭 키가 아니어도 됨 (예: 1자녀 정책에서 "보호자 → 학생명").

**완전 vs 부분 함수 종속**:
- **완전 함수 종속** — X의 어떤 진부분집합 X'도 `X' → Y` 성립 안 함
- **부분 함수 종속** — X의 어떤 부분집합이 Y를 결정

### 8. 제2정규형 (2NF)

**1NF + 키가 아닌 속성이 모두 기본키에 완전 함수 종속**.

부분 함수 종속이 제거됨. 예:

```
수강(학번, 과목번호, 지도교수, 학과, 성적)  PK={학번, 과목번호}
```
- `{학번, 과목번호} → 성적` (완전)
- `학번 → 지도교수, 학과` (부분 종속, 2NF 위반)

**분해** → `학생(학번, 지도교수, 학과)` + `수강(학번, 과목번호, 성적)`.

## 강의 12 — 3NF · BCNF · 기타

### 1. 2NF의 이상 상태

2NF를 만족해도 **이행적 함수 종속** 때문에 이상 발생 가능.

```
사원정보(사번, 이름, 부서번호, 부서명)  PK={사번}
FD: 사번 → 부서번호, 부서번호 → 부서명
→ 사번 → 부서명 (이행적)
```

- **삽입 이상**: 직원 없이 신규 부서 생성 불가
- **삭제 이상**: 직원 퇴사로 부서 정보 소실
- **갱신 이상**: 부서명 변경 시 모든 사원 행 수정 필요

### 2. 이행적 함수 종속 (Transitive FD)

`A → B` 이고 `B → C` 이면 `A → C`가 이행적.

### 3. 제3정규형 (3NF)

**2NF + 키가 아닌 속성이 기본키에 이행적 함수 종속 되지 않음**.

2NF 이상 해결 방법 = 이행적 FD **무손실 분해**.

예: `사원정보` → `사원(사번, 이름, 부서번호)` + `부서(부서번호, 부서명)`.

### 4. 3NF의 한계 · BCNF

**3NF를 만족해도 이상 발생 가능** — 특히:
- 복수 후보키
- 후보키가 여러 속성으로 구성
- 후보키 속성이 서로 중첩

예:
```
수강과목(학번, 과목, 교수)
후보키: {학번, 과목}, {학번, 교수}    PK={학번, 과목}
FD: {학번, 과목} → 교수, 교수 → 과목
```
"교수 → 과목" 때문에 이상 발생 가능.

### 5. BCNF (Boyce-Codd Normal Form)

**릴레이션 R의 모든 결정자가 후보키인 경우** R은 BCNF.

- R이 BCNF → R은 1·2·3NF 모두 만족
- = **강력한 3NF (Strong 3NF)**
- DB 설계 목표 = 모든 릴레이션 BCNF(또는 3NF)

### 6. 이진 릴레이션의 속성

모든 **이진 릴레이션(속성 2개)** 은 자동으로 3NF이자 BCNF — 이행적 FD가 존재하려면 최소 3개 속성 필요하므로.

### 7. 고급 정규형 (개요)

- **제4정규형 (4NF)** — 다치 종속(Multivalued Dependency) 기반
- **제5정규형 (5NF)** — 조인 종속(Join Dependency) 기반

## 정규화 진행 흐름

```
1NF (원자성)
  ↓ 부분 FD 제거
2NF (키에 완전 FD)
  ↓ 이행적 FD 제거
3NF (이행 없음)
  ↓ 모든 결정자를 후보키로
BCNF (= Strong 3NF)
  ↓ (고급)
4NF (다치 종속) → 5NF (조인 종속)
```
