# OS Lec7 — 교착상태 (Deadlock)

운영체제 강의 (2025 봄학기) 7장.

Lec3의 상태 전이 다이어그램에서 **Asleep 상태 중 영구 대기** 케이스의 심화. Lec6의 상호배제가 "동시성 문제 1"이라면 Deadlock은 "자원 할당 순환 대기" 문제. [[Edsger Dijkstra]]가 이번에도 주요 기여자로 **Banker's algorithm** 창안자로 등장.

## 요약

Deadlock은 프로세스가 발생 가능성 없는 이벤트를 기다리는 상태로, Blocked/Asleep 및 Starvation과 구분된다. 자원은 5축(HW/SW, Preemptible, Total/Partitioned, Exclusive/Shared, SR/CR)으로 분류되며, Deadlock을 유발하는 조합은 **Non-preemptible + Exclusive + SR**이다. 발생 필요 조건은 4개 — 자원 특성 2(Exclusive use·Non-preemptible)와 프로세스 특성 2(Hold and wait·Circular wait). 해결 방법 3가지: **Prevention**(4조건 중 하나 제거, 비현실적), **Avoidance**(safe state 유지; **Banker's algorithm** by Dijkstra, **Habermann's algorithm** multi-resource 확장), **Detection+Recovery**(RAG + Graph reduction → Process termination/Resource preemption/Checkpoint-restart). Avoidance는 최악을 가정하고, Detection은 최선을 가정한 후 복구에 의존한다.

## 핵심 포인트

### 1. Deadlock vs Blocked vs Starvation

| 구분 | 의미 | 해결 가능성 |
|---|---|---|
| **Blocked/Asleep** | 발생 **가능성 있는** 이벤트 대기 (I/O 완료 등) | 자연 해결 |
| **Deadlock** | 발생 **가능성 없는** 이벤트 대기 | 영구 불가 |
| **Starvation** | Ready에 있으나 무한 대기 (스케줄링 밀려남) | aging 등으로 해결 |

상태 전이 그림 상: `asleep` 내부의 `deadlocked` 노드에서는 **transition impossible**.

### 2. 자원 분류 5축

| 축 | 구분 | 예 |
|---|---|---|
| 일반 | HW / SW | Processor·memory·disk / file·message·signal |
| 선점성 | **Preemptible** / **Non-preemptible** | Processor·memory / Disk drive (rollback 필요) |
| 할당 단위 | Total / Partitioned | Processor·disk / Memory |
| 동시 사용 | **Exclusive** / Shared | Processor·memory·disk / Program·shared data |
| 재사용 | **SR (Serially-reusable)** / CR (Consumable) | Processor·memory·program / Signal·message |

**Deadlock 유발 자원 조합**: **Non-preemptible + Exclusive + SR**. (할당 단위는 무관. CR는 모델이 너무 복잡해 별도.)

### 3. Deadlock 예제 (2 proc × 2 resource)

P1이 R2를 요청해 확보 후 R1을 요청, P2가 R1을 요청해 확보 후 R2를 요청 → **순환 대기 발생 t5~**.

### 4. Deadlock Model

#### (a) Graph Model

- **Node**: 프로세스 노드 (P1, P2, ...) + 자원 노드 (R1, R2, ...).
- **Edge**:
  - `Pi → Rj`: Pi가 Rj를 **요청** (대기 중).
  - `Rj → Pi`: Rj가 Pi에게 **할당**됨.
- 순환(cycle) 발견이 deadlock 시그널.

#### (b) State Transition Model

프로세스 수·자원 수 조합으로 가능한 상태를 모두 나열한 그래프. 예: 2 proc × A-type 2 unit → Sij 상태 표 + 전이 화살표. 특정 상태 S33은 **deadlock state**로 빨간 표시.

### 5. Deadlock 4대 필요 조건 (all required)

| 특성 | 조건 | 의미 |
|---|---|---|
| **자원** | **Exclusive use of resources** | 한 번에 한 프로세스만 사용 |
| **자원** | **Non-preemptible resources** | 강제 회수 불가 |
| **프로세스** | **Hold and wait (Partial allocation)** | 자원 일부 hold + 추가 요청 |
| **프로세스** | **Circular wait** | 대기 순환 형성 |

### 6. 3대 해결 방법 개관

```
Prevention ─── 4조건 중 하나 제거 (비현실적)
Avoidance ──── Safe state 유지 (사전 감시)
Detection+Recovery ── 발생 허용 + 사후 복구
```

### 7. Deadlock Prevention

4개 필요 조건 중 **하나 제거**:

| 제거 조건 | 방법 | 한계 |
|---|---|---|
| Exclusive use | 모든 자원 공유 허용 | 현실적 불가능 |
| Non-preemptible | 모든 자원 선점 허용 / 취소+재시작 | 비현실적, 자원 낭비 |
| Hold and wait | **필요 자원 한번에 모두 할당 (Total allocation)** | 자원 낭비, 무한 대기 |
| Circular wait | **자원에 순서 부여** (증가 방향만 요청) | 자원 낭비 |

→ Deadlock 절대 발생 X, 그러나 **Low device utilization·Reduced throughput** — 비현실적.

### 8. Deadlock Avoidance

- **시스템을 항상 safe state로 유지**. 자원 할당 요청을 동적으로 검사·보류.
- **Safe state**: 모든 프로세스가 정상 종료 가능 (**safe sequence** 존재).
- **Unsafe state**: deadlock 될 **가능성** (반드시 발생은 아님).

**가정**:
- 프로세스 수·자원 종류·수 고정.
- 프로세스의 **max claim**(최대 요구 자원 수) 사전 파악.
- 자원 사용 후 반납.

→ **Not practical** (가정이 강함).

#### (a) Dijkstra's Banker's Algorithm
- [[Edsger Dijkstra]] 제안. **1 resource type**, 다수 unit.
- 테이블: Process-ID · Max. Claim · Cur. Alloc. · Additional Need.
- 요청 시: 가상 할당 후 **safe sequence 존재** 여부 검사 → accept / reject.
- 예: 10 units, 3 processes. P1 요청 → accept (safe 유지). P2 요청 → reject (unsafe).

#### (b) Habermann's Algorithm
- **Multi resource types + multi units** 확장.
- 3 types (Ra=10, Rb=5, Rc=7), 5 processes 예제.
- Available resource vector + Additional Need matrix → safe sequence 탐색.

**한계**:
- High overhead (지속 감시).
- Low utilization (safe state 유지를 위한 유휴 자원).
- Not practical.

### 9. Deadlock Detection

- Deadlock 방지를 위한 사전 작업 없음 → 발생 허용.
- **주기적 검사**: 시스템 deadlock 여부 + 어떤 프로세스인지.
- 도구: **RAG (Resource Allocation Graph)**.

#### (a) RAG 정의
- Directed graph G=(N, E). **Bipartite** (Np, Nr).
- Np = {P1, ..., Pn}, Nr = {R1, ..., Rm}.
- `e = (Pi, Rj)`: 요청 / `e = (Rj, Pi)`: 할당.
- 각 Rk는 tk (단위 자원 수), `|(a,b)|` = edge 수.

#### (b) Graph Reduction (탐지 절차)
- **Unblocked process**: 필요 자원 모두 할당받을 수 있는 프로세스.
  - `∀j (|(Pi, Rj)| ≤ tj − Σ|(Rj, Pk)|)`
- 절차:
  1. Unblocked process에 연결된 모든 edge 제거.
  2. Unblocked process가 없을 때까지 반복.
- 결과:
  - **Completely reduced**: deadlock 없음.
  - **Irreducible**: 1+ 프로세스가 deadlock.

- **High overhead** (검사 주기, 노드 수).
- Low-overhead 특수 케이스:
  - **Case-1**: Single-unit resources → **cycle detection**.
  - **Case-2**: Single-unit request in expedient state → **knot detection**.

### 10. Avoidance vs Detection 대비

| 관점 | Avoidance | Detection |
|---|---|---|
| 가정 | 최악 (앞일 고려) | 최선 (현재 상태만) |
| Deadlock | 발생 X | 발생 허용 |
| 사후 처리 | 불필요 | Recovery 필요 |

### 11. Deadlock Recovery

#### (a) Process Termination
- Deadlock 상태 프로세스 중 일부 강제 종료 → 재시작.
- **Termination cost model**: priority·type·누적 실행 시간·남은 시간·회계 비용.
- 선택 전략:
  - **Lowest-termination cost first**: 단순, low overhead, 불필요 종료 가능.
  - **Minimum cost recovery**: deadlock 해소 최소 비용. 모든 경우의 수 → **O(2^k)** complex.

#### (b) Resource Preemption
- Deadlock 해결 위해 선점할 자원 선택 → 해당 프로세스 강제 종료 (deadlock 상태 아닌 프로세스도 희생 가능).
- Preemption cost model + minimum cost recovery. **O(r)**.

#### (c) Checkpoint-Restart
- 프로세스 수행 중 주기적으로 **context 저장** (checkpoint-1, 2, ..., k).
- 강제 종료 후 **가장 최근 checkpoint로 rollback** → 재시작.
- 처음부터 재시작보다 효율적.
