# OS Lec4 — 스레드 관리

운영체제 강의 (2025 봄학기) 4장.

Lec3에서 예고된 **Context switch overhead의 해법**. 프로세스에서 "자원 할당 단위"와 "제어/실행 단위"를 분리하여, 후자를 경량화한 **스레드(Light Weight Process)** 도입.

## 요약

프로세스는 **자원 할당 단위**, 스레드는 **제어/실행 단위**로 역할이 분리된다. 스레드는 Thread ID·Register set(PC·SP)·Stack만 고유하게 갖고, 코드·전역 데이터·힙·자원은 같은 프로세스 내 다른 스레드와 공유한다. 응답성·자원 공유·경제성·멀티 프로세서 활용의 4대 장점이 있으며, 특히 경제성은 Lec3의 context switch overhead 문제를 직접 해소한다. 구현은 3가지 — **사용자 수준(User Thread, n:1)**: 라이브러리 기반으로 유연하나 하나 block 시 전체 대기. **커널 수준(Kernel Thread, 1:1)**: OS 직접 관리로 독립 병행 가능하나 overhead 큼. **혼합형(n:m)**: 경량 프로세스 매핑으로 효율과 유연을 모두 얻음.

## 핵심 포인트

### 1. 프로세스 vs 스레드

| 구분 | 프로세스 | 스레드 |
|---|---|---|
| 역할 | **자원 할당**의 단위 (소유자) | **제어/실행**의 단위 (프로세서 활용의 기본 단위) |
| 관계 | 스레드들의 컨테이너 | 프로세스에 속함 |

**전통적 프로세스 = 단일 스레드 프로세스**.

### 2. Thread = Light Weight Process (LWP)

**구성 요소** (스레드 고유):
- **Thread ID**
- **Register set** (PC, SP 등)
- **Stack** (local data)

**공유** (같은 프로세스 내 다른 스레드와):
- 코드
- 전역 데이터
- 힙(Heap)
- 자원 (파일, I/O 등)

메모리 공간 그림: 하나의 프로세스 주소 공간 내에서 코드·데이터·힙은 모든 스레드가 공유하고, 스택 영역만 스레드별 분할. 각 스레드는 자기만의 SP와 PC를 가짐.

### 3. 스레드의 4대 장점

- **사용자 응답성 (Responsiveness)**: 일부 스레드가 지연/block 상태가 되어도 다른 스레드는 작업 계속. 예) 게임의 화면 출력·사용자 입력·스피커 스레드가 독립 동작.
- **자원 공유 (Resource sharing)**: 같은 address space 공유로 커널 개입 회피 → 효율 증가.
- **경제성 (Economy)**: 프로세스 생성·context switch 대비 저비용. → **Lec3의 context switch overhead 해법의 정석**.
- **멀티 프로세서 활용**: 병렬 처리 → 성능 향상.

### 4. 스레드 구현 3모델

#### (a) 사용자 수준 스레드 (User Thread) — n:1 매핑

- **사용자 영역의 스레드 라이브러리**로 구현:
  - POSIX threads (pthreads)
  - Win32 threads
  - Java thread API
- **커널은 스레드 존재를 모름** — 프로세스 단위로만 자원 할당.
- 장점: 생성·관리 부하 적음, 유연한 관리, **높은 이식성(portability)**.
- 단점: **single-threaded kernel에서 하나 block → 모든 스레드 대기** (커널은 프로세스만 본다).
- 매핑: **n개 사용자 스레드 → 1개 커널 스레드 (n:1)**.

#### (b) 커널 수준 스레드 (Kernel Thread) — 1:1 매핑

- OS(Kernel)가 직접 관리. 커널 영역에서 생성·관리.
- **TCB (Thread Control Block)** 관리 — PCB의 스레드판.
- 장점: 커널이 **각 스레드를 개별 관리** → 프로세스 내 스레드 **병행 수행**, 하나 block도 다른 스레드 진행 가능.
- 단점: Context switching 등 **부하(overhead) 큼**.
- 매핑: **1개 사용자 스레드 ↔ 1개 커널 스레드 (1:1)**.

#### (c) 혼합형 스레드 — n:m 매핑

- **n개 사용자 스레드 ↔ m개 커널 스레드 (n > m)**.
- 중간에 **경량 프로세스(Light Weight Process)** 레이어가 매핑.
- 사용자는 원하는 수만큼 스레드 사용, 커널 스레드는 할당된 사용자 스레드 중 하나가 block 되어도 다른 스레드 수행 가능 → **병행 처리**.
- **효율 + 유연** 모두 확보.

### 5. 모델 비교 요약

| 모델 | 매핑 | 관리 주체 | 제어 블록 | Block 전파 | Overhead |
|---|---|---|---|---|---|
| User Thread | n:1 | 라이브러리 (사용자 영역) | TCB (사용자 영역) | 전체 대기 | 낮음 |
| Kernel Thread | 1:1 | OS(Kernel) | TCB (커널 영역) | 독립 | 높음 |
| 혼합형 | n:m | 라이브러리 + 커널 | 양쪽 | 부분 독립 | 중간 |
