# OS Lec10 — 가상 메모리 관리 (Virtual Memory Management)

운영체제 강의 (2025 봄학기) 10장.

Lec9에서 기법(Paging·Segmentation·Hybrid)을 배웠다면, Lec10은 그 **성능 최적화** — page fault rate를 낮추기 위한 6대 전략과 11종 교체 알고리즘. [[Edsger Dijkstra]]·[[Peter Denning]]·[[László Bélády]] 등 OS 거장들의 이름이 대거 등장 (Denning의 Working Set 1968, Belady의 MIN algorithm 1966 및 FIFO anomaly).

## 요약

가상 메모리 관리의 목적은 **page fault rate 최소화**이며, cost model은 IFT(inter-fault time) 기반이다. HW 지원(TLB, reference/update bit vectors)과 SW 전략(**Allocation·Fetch·Placement·Replacement·Cleaning·Load control**)이 결합한다. 대부분 시스템은 **Demand fetch + Demand cleaning**을 사용하며, Load control은 multi-programming degree를 **plateau 영역**에 유지하여 **thrashing** 회피. Replacement는 Fixed allocation 8종(**MIN**[Belady, optimal/unrealizable] · Random · FIFO[+Belady's anomaly] · **LRU**[실사용 최다] · LFU · NUR · Clock[IBM VM/370] · Second chance)과 Variable allocation 3종(**WS**[Denning 1968] · PFF · VMIN)으로 분리. 모두 Lec1의 **locality** 개념에 기반. 기타 고려사항은 page size trade-off · program restructuring · TLB reach.

## 핵심 포인트

### 1. Cost Model for VM System

- **Page fault frequency**: 발생 빈도.
- **Page fault rate** `F(ω)`: ω 기간 중 page fault 수 / |ω|.
  - `ω = r₁r₂…r_T` (page reference string), `rᵢ ∈ {0, …, N-1}`.
- 설계 원칙: **Context switch 및 kernel 개입 최소화** → 시스템 성능 향상.

### 2. Hardware Components

- **Address translation device**: 주소 사상 장치. 예) TLB, dedicated page-table register, cache.
- **Bit vectors** (PMT 내):
  - **Reference bit (r)**: 참조되면 1, 주기적 초기화 O. 최근 참조 page 추적.
  - **Update bit (m)** (= modified / dirty / write bit): 수정되면 1, 주기적 초기화 **없음**. `m=1` → swap device와 불일치 → **write-back 필요**.

### 3. Software Components — 6대 전략

| 전략 | 질문 |
|---|---|
| **Allocation** | 프로세스에게 **얼마** 줄 것인가? |
| **Fetch** | **언제** 적재할 것인가? |
| **Placement** | **어디에** 적재할 것인가? |
| **Replacement** | **어떤 page와 교체** 할 것인가? |
| **Cleaning** | **언제 write-back** 할 것인가? |
| **Load control** | Multi-programming degree 조절 |

#### Allocation
- **Fixed allocation**: 고정 크기 / **Variable allocation**: 유동.
- 너무 크면 낭비, 너무 작으면 PF rate ↑.

#### Fetch
- **Demand fetch (demand paging)**: 참조된 것만. PF overhead 존재. **실제 대부분 시스템 채택**.
- **Anticipatory fetch (pre-paging)**: 미리 예측 적재. Hit ratio 민감.

#### Placement
- **Paging에서는 불필요**.
- Segmentation에서만: First-fit · Best-fit · Worst-fit · Next-fit.

#### Cleaning
- **Demand cleaning**: page 내려올 때 write-back. **실제 대부분 채택**.
- **Anticipatory cleaning (pre-cleaning)**: 미리 write-back.

#### Load Control
- **Under-loaded**: 자원 낭비.
- **Plateau (고원)**: 최적 구간.
- **Over-loaded** → **Thrashing**: 과도한 PF 발생 → throughput 급락.

```
throughput
    │    ┌────┐
    │   /      \__________thrashing
    │  /                  ↓
    │_/_________________________
    │ underloaded  plateau  overloaded
    └──────────────────────────→ MP degree
```

### 4. Locality (Lec1·9 재등장)

- **공간적 지역성 (Spatial)**: 인접 영역 재참조. Array·structure.
- **시간적 지역성 (Temporal)**: 최근 참조 재참조. Loop.
- 예) `for i=1 to 1000: A[i] = B[i] + C[i]` → 8006번 참조 중 4개 page만 집중 접근.

### 5. Replacement Strategies — Fixed Allocation (8종)

#### (a) MIN (OPT) algorithm
- **Belady, 1966**. [[László Bélády|Bélády]].
- **Page fault frequency 최소화 증명됨** (optimal).
- 기법: 앞으로 **가장 오랫동안 참조되지 않을 page** 교체.
- **Unrealizable** — reference string 사전 지식 필요. **성능 평가 도구로만** 사용.

#### (b) Random
- 무작위. Low overhead. **No policy**.

#### (c) FIFO (First In First Out)
- 가장 오래된 page 교체. 적재 시간 기록 필요.
- **Locality 고려 없음** → 자주 쓰는 page도 교체될 수 있음.
- **Belady's anomaly (FIFO anomaly)**: **Frame 수 증가에도 PF 수가 증가**하는 반직관 현상.
  - 예) ω=1 2 3 4 1 2 5 1 2 3 4 5: 3-frame=9 PF, 4-frame=10 PF.

#### (d) LRU (Least Recently Used)
- 가장 오랫동안 참조되지 않은 page 교체. 참조 시 시간 기록.
- **Locality 기반** → MIN에 근접. **실제 가장 많이 활용**.
- 단점: 시간 기록 overhead, loop 크기 > frame 수이면 PF 폭증.

#### (e) LFU (Least Frequently Used)
- 가장 참조 횟수 적은 page 교체. Tie-breaking rule 필요 (예: FIFO).
- LRU 대비 적은 overhead. 최근 적재 page가 교체될 위험.

#### (f) NUR (Not Used Recently) — **LRU approximation**
- Reference bit (r), Update bit (m) 사용.
- 교체 순서: **(0,0) → (0,1) → (1,0) → (1,1)**.

#### (g) Clock algorithm
- **IBM VM/370 OS** 채택.
- Reference bit, **주기적 초기화 없음**. Pointer(시계바늘)로 순회.
- r=0 → 교체 / r=1 → reset 후 이동.
- FIFO + LRU(NUR) 특성 혼합.

#### (h) Second chance algorithm
- Clock + **Update bit 고려**.
- (0,0) 교체 / (0,1) → cleaning list + 이동 / (1,0) → (0,0) 이동 / (1,1) → (0,1) 이동.

#### Other algorithms (언급만)
- **Additional-reference-bits**: 여러 reference bit로 history register.
- **MRU**: LRU 정반대. **MFU**: LFU 정반대.

### 6. Replacement Strategies — Variable Allocation (3종)

#### (a) Working Set (WS) algorithm
- **Denning, 1968**. [[Peter Denning|Denning]].
- **Working set** `W(t, ∆)`: `[t-∆, t]` 동안 참조된 page 집합 (∆ = window size).
- **Locality 기반**. Working set을 항상 메모리에 유지 → PF rate / thrashing 감소.
- **Window size 고정, memory allocation 가변**.
- ∆ 값이 성능을 결정. WS size는 프로그램 size에 수렴.
- 단점: Residence set을 PF 없어도 **지속 관리** → overhead.

#### (b) Page Fault Frequency (PFF) algorithm
- **IFT(inter-fault time) 기반**. 
  - `IFT > τ` (낮은 PF rate) → frame 수 유지/감소, (t_{c-1}, t_c] 참조 page만 유지.
  - `IFT ≤ τ` (높은 PF rate) → frame 수 증가, 기존 유지 + 현재 page 추가.
- τ: threshold (system parameter).
- **Page fault 발생 시에만 갱신** → low overhead. (WS 대비 장점).

#### (c) Variable MIN (VMIN) algorithm
- **Variable allocation의 optimal** (평균 할당량 + PF 수 모두 고려).
- **Unrealizable**. `[t, t+∆]` 보고 page 유지 여부 결정.
- 최적 ∆ = R/U (R: PF 처리 비용, U: page 유지 비용).

### 7. Other Considerations

#### Page size
- **No best answer**. 점점 커지는 경향 (HW 발전으로 PF 처리 비용 상대적 ↑).
- Typical: 2⁷ (128 B) ~ 2²² (4 MB).

| | Small page | Large page |
|---|---|---|
| Page table / PF 수 | **많음** | 적음 |
| Kernel overhead | 높음 | 낮음 |
| 내부 단편화 | 감소 | 증가 |
| I/O 시간 | 증가 | 감소 |
| Locality | 향상 | 저하 |
| Page fault | 증가 | **감소** |

#### Program restructuring
- 사용자가 VM 기법을 이해하면 프로그램 재구성으로 성능 향상.
- 예) Row-major C 배열에서 `for j { for i { zar[i][j] }}` → `for i { for j { zar[i][j] }}`로 locality 활용.

#### TLB reach
- TLB가 커버하는 메모리 크기. Lec9 TLB의 연장선.
