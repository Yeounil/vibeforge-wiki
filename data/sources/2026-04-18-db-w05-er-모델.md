# DB 5주차 — ER 모델 & ER 다이어그램

DB 강의 (2026 봄학기)의 5주차. ⑨ [[ER 모델]] 소개와 개념, ⑩ 다양한 ERD 표기법(바커·IE·UML 등).

## 강의 9 — ER 모델

### 1. 개요

- **1976년 [[Peter Chen]]** 이 제안한 **개념적 데이터 모델**.
- 현실 세계를 **개체 타입**과 **관계 타입** 기반으로 모델링.
- 산출물: **[[ER 다이어그램]]** (ERD, Entity-Relationship Diagram).

### 2. 3대 구성요소

**개체(Entity) · 속성(Attribute) · 관계(Relationship)**.

### 3. 개체 (Entity)

업무상 지속 관심 대상. 동질성을 지닌 집합.

**개체가 되기 위한 조건 6가지**
1. 업무에 필요·관리 대상 정보
2. 유일 식별자 존재 가능
3. 영속적으로 존재
4. 업무 프로세스가 이용
5. 속성 포함
6. 다른 개체와 1개 이상의 관계

**계층 구조**: 개체 타입 → 개체 → 속성 → 속성값.
- 하나의 개체 타입 = 2개 이상 개체
- 하나의 개체 = 2개 이상 속성
- 하나의 속성 = 1개 속성값만

### 4. 속성 분류

| 분류 | 설명 |
|---|---|
| **기본 속성** | 업무 분석으로 바로 정의. 가장 일반적이고 많음. |
| **설계 속성** | 모델링 중 새로 만들거나 변형 (예: 코드, 일련번호). |
| **파생 속성** | 다른 속성의 영향 받아 계산. **적게** 정의하는 게 좋음 (정합성 위험). |

추가 유형: 복합 vs 단순, 단일값 vs 다중값, 유도 vs 저장, NULL.

### 5. 식별자 (Identifier = Key)

인스턴스를 식별하는 속성. 논리 모델링에서 **식별자**, 물리 모델링에서 **키** 라 부름.

**복합 식별자** — 2개 이상 속성 조합.

5가지 유형:
- **본질 식별자** — 집합의 본질을 설명하는 의미상 주어
- **후보 식별자** — 유일 식별 가능 속성 (집합)
- **대체(보조) 식별자** — 원래 식별자 대신 사용 가능한 속성
- **인조 식별자** — 기존을 대체하기 위해 새로 도입된 임의 값 (예: 사원번호)
- **실질 식별자** — 공식적으로 부여된 식별자

### 6. 관계 (Relationship)

개체 간 연관성. **이항 관계**가 주류 (삼항 이상은 드묾).

**분류 기준 1 — 목적**
- **존재에 의한 관계** — "소속된다" (이벤트 없이 성립)
- **행위에 의한 관계** — "주문한다" (행위 발생으로 생성)

**분류 기준 2 — 매핑 카디널리티** (함수성 활용)

| 차수 | 함수성 | 예 |
|---|---|---|
| **1:1** | `fx: x→y`, `fy: y→x` 양쪽 | 신랑 - 신부 |
| **M:1** | `fx: x→y`만 | 교수 - 학과 |
| **1:M** | `fy: y→x`만 | 엄마 - 자식 |
| **M:M** | 양쪽 다 없음 | 등록 - 과목 |

**1:1** — 현실에 드묾. 업무 흐름에 따른 분할에서 자주.
**1:M** — **가장 흔한** 형태 (부모-자식 구조).
**M:M** — 데이터 모델링 완료 후에는 존재하지 않음 → 새 **관계 개체(Relation Entity / Intersection Entity)** 로 해소.

### 7. 참여 유형

- **전체 참여 (Total Participation)** — 모든 개체가 관계에 참여 (예: 학과 - 교수)
- **부분 참여 (Partial Participation)** — 일부만 (예: 군대 - 여성)

조합: **필수-필수 · 필수-선택 · 선택-필수 · 선택-선택**.

### 8. 존재 종속 & 약한 개체

- **존재 종속(Existence Dependence)** — B의 존재가 A에 종속 → B는 A에 존재 종속.
  - A = **주 개체 (Dominant)**, B = **종속 개체 (Subordinate)**.
  - 예: 대부 - 상환 (상환은 대부에 종속).
- **약한 개체 타입(Weak Entity)** — 자기 속성만으로 키를 명세할 수 없음.
  - **구별자 / 부분키 (Partial Key)** — 강한 개체와 연관된 약한 개체들을 구별.
  - **식별 관계 타입** — 약한 개체를 강한 개체에 연결.

## 강의 10 — ER 다이어그램 표기법

### 1. ERD 역할

도식화된 업무 분석 결과. **정보 공학 기반 모델링의 핵심 산출물**. 누구나 공통 시각으로 파악 가능 → 의사소통 도구.

### 2. 주요 표기법 6종

| 표기법 | 특징 | 용도 |
|---|---|---|
| **원조 (Chen)** | 개체=사각형, 관계=마름모, 속성=타원 | 대학 교재, 실무 미사용 |
| **IDEF1X** | 마름모·원 사용 | 소수 활용 (ERWin) |
| **IE (Crow's Foot)** | 1981 Clive Finkelstein·James Martin. 다(Many)에 **까마귀 발** 기호 | **실무 주류**. 데이터 분석·DB 설계에 유용 |
| **바커 (Barker)** | 영국 CACI → Richard Barker. 오라클이 Case Method로 채택 | 실무 (오라클 계열) |
| **Min-MAX/ISO** | 기수성 정교 표현 | 드묾 |
| **UML** | 스테레오타입 `<<Entity>>` | 객체지향 통합 (Rational Rose) |

IE와 바커는 상호 전환 가능 — 하나만 알면 다른 것도 이해 쉬움.

### 3. 바커 표기법 핵심 (실습 대상)

- **개체**: 네 모서리가 둥근 **소프트박스** + 개체명.
- **속성 상태**:
  - `*` (Mandatory) — 필수
  - `o` (Optional) — 선택
- **식별자**: `#` 기호 표시 (복합 식별자는 `#` 반복). 논리 단계에서 "식별자", 물리 단계에서 "키"라 부름.
- **서브타입**: 슈퍼타입 안에 상자로 표기 (공간 절약, 중복 불허 = 상호 배타).

### 4. 바커 관계 구문 (7단계)

```
[개체1 임의의 하나는] [단 하나의 | 하나 이상의] [개체2를] [관계명이] [반드시 되어야 한다 | 될 수도 있다]
```

예: "각 사원은 하나의 부서에 반드시 근무한다 / 각 부서에 한 명 이상의 사원이 근무할 수도 있다."

### 5. 확장된 ER (EER)

초기 ER 모델 + **서브타입(Subtype)** → EER (Extended Entity-Relationship Model).
