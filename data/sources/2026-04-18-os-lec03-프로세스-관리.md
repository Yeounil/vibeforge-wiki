# OS Lec3 — 프로세스 관리

운영체제 강의 (2025 봄학기) 3장.

Lec2에서 맵만 잡은 **프로세스 관리**의 본격 도입. 프로세스 정의·PCB·상태 전이·Context switching·Interrupt — 이 강의 전반에서 가장 자주 재등장할 개념들이 여기서 정립된다.

## 요약

Job(프로그램+데이터, 실행 전)과 Process(커널에 등록된 실행 단위, **능동적 개체**, PCB 할당)를 구분한다. 자원은 **수동적 개체**로 HW/SW로 나뉜다. **PCB**는 커널 공간에 존재하며 PID·스케줄링·상태·메모리 정보·I/O 상태·**context save area**·계정 정보를 담고, 그 참조·갱신 속도가 OS 성능의 핵심이다. 프로세스 상태는 자원 할당 상태에 따라 Running/Ready/Asleep(Active, 메모리 O)과 Suspended ready/blocked(메모리 X)로 나뉘며, Created·Terminated를 포함한 상태 전이 다이어그램이 핵심. **Context switching**은 register context를 PCB 영역에 저장·복구하는 작업으로 커널 개입 필수이며, overhead가 OS 성능에 큰 영향을 주어 **스레드**(Lec4)가 해법으로 예고된다. **Interrupt**는 예상치 못한 외부 이벤트로, 7종 분류 + 3단계 처리 과정(발생→handling→service/ISR)을 갖는다.

## 핵심 포인트

### 1. Job vs Process

| 구분 | Job / Program | Process |
|---|---|---|
| 구성 | 프로그램 + 데이터 | 커널 등록된 Job |
| 상태 | 실행 요청 **전** | 실행 **중/관리 하** |
| 개체 성격 | — | **능동적(active entity)** |
| 관리 | — | 커널 + PCB |

**자원(Resource)**은 대비되는 **수동적 개체(passive entity)** — 커널이 할당·반납.
- HW resource: processor, memory, disk, monitor, keyboard ...
- SW resource: message, signal, files, installed SW ...

### 2. 프로세스 분류 3축

- **역할**: user process(응용) / system process(OS가 실행)
- **관계**: independent(단독) / cooperating(상호작용)
- **상호작용**: foreground(사용자와 대화) / background(비대화)

### 3. PCB (Process Control Block)

- 커널 공간(kernel space) 내 존재. **프로세스 생성 시 함께 생성**.
- 관리 정보:
  - **PID** (Process IDentification number)
  - **스케줄링 정보** (우선순위 등)
  - **프로세스 상태** (자원 할당/요청)
  - **메모리 관리 정보** (page table, segment table)
  - **입출력 상태 정보** (할당된 I/O 장치·파일)
  - **Context save area** (레지스터 상태 저장)
  - **계정 정보** (자원 사용 시간)
- 특징:
  - PCB 정보 스펙은 **OS별로 다름**.
  - **PCB 참조·갱신 속도 = OS 성능 결정 핵심 요소**.

### 4. 프로세스 상태 (Process States)

프로세스–자원 상호작용에 의해 결정. 메모리 할당 여부로 Active(swapped-in) / Suspended(swapped-out) 구분.

| 대분류 | 세부 상태 | 프로세서 | 기타 자원 | 메모리 |
|---|---|---|---|---|
| **Active** | Running | O | O | O |
|  | Ready | X | O | O |
|  | Blocked / Asleep | X | X | O |
| **Suspended** | Suspended ready | X | — | X |
|  | Suspended blocked | X | X | X |

+ 특별 상태:
- **Created**: 작업 등록 직후. PCB 할당·생성. 가용 메모리 여부에 따라 Ready 또는 Suspended ready로 전이.
- **Terminated/Zombie**: 모든 자원 반납 후 PCB 일부만 남아 있는 상태 (이후 관리용 정보 수집).

### 5. 상태 전이 다이어그램

주요 전이:

- `Job submit → Created`
- `Created → Ready` (memory allocated) / `Created → Suspended ready` (waiting memory allocation)
- `Ready → Running`: **dispatch (schedule)** — 프로세서 할당.
- `Running → Ready`: **timer run-out (preemption)** — 스케줄링에 의한 빼앗김 (time-out·priority change).
- `Running → Asleep`: **sleep (block)** — I/O 등 자원 요청. system call로 발생.
- `Asleep → Ready`: **wakeup**.
- `Running → Terminated`: **exit**.
- **Swap-out (suspend)** / **Swap-in (resume)**: Active ⇄ Suspended. 메모리 image를 **swap device**(특별한 파일시스템)에 보관. 커널 또는 사용자가 발생시킴.
- `Suspended blocked → Suspended ready`: **wakeup** (메모리 없이도 I/O 완료 가능).

### 6. Context Switching (문맥 교환)

- **Context** = 프로세스 관련 정보 집합.
  - CPU register context ⇒ in CPU
  - Code & data, Stack, PCB ⇒ in memory
- **Context saving**: 현재 프로세스 register context → memory(PCB 영역) 저장.
- **Context restoring**: memory → register로 복구.
- **Context switching ≅ Process switching**: 실행 중 프로세스의 context 저장 + 다음 실행 프로세스의 context 복구. **커널이 개입**.
- 4단계 (그림 기준): ① 현재 레지스터 → memory (saving) ② 현재 프로세스 out ③ 다음 프로세스 in ④ memory → 레지스터 (restoring).

### 7. Context Switch Overhead

- OS마다 비용 다름. **OS 성능에 큰 영향**.
- **불필요한 context switching 줄이기가 핵심 과제**.
- 해법 예고: **스레드(thread) 사용** → [[2026-04-18-os-lec04-스레드-관리|Lec4]].

### 8. Interrupt (인터럽트)

**예상치 못한 외부 이벤트 (Unexpected, external events)**.

종류 7:

| 종류 | 예 |
|---|---|
| **I/O interrupt** | 디스크 읽기 완료, 키 입력 |
| **Clock interrupt** | 시간 quantum 만료 (→ preemption) |
| **Console interrupt** | 콘솔 사용자 명령 |
| **Program check interrupt** | 0 division, 접근 위반 |
| **Machine check interrupt** | HW 오류 |
| **Inter-process interrupt** | 프로세스 간 신호 |
| **System call interrupt** | 응용 → 커널 요청 |

### 9. Interrupt 처리 과정 (3단계)

1. **인터럽트 발생** → 프로세스 중단 (**커널 개입**).
2. **Interrupt handling**: 발생 장소·원인 파악 → 인터럽트 서비스 결정.
3. **Interrupt service**: **ISR (Interrupt Service Routine)** 호출 → **Context saving** → Scheduler → 다음 프로세스 **Context restoring**.

그림 흐름: `Pi → Interrupt → Kernel(IH, IS) → Scheduler → Pj`.

## 이어지는 Lec

- **Lec4 (스레드)**: Context switching overhead를 줄이기 위한 해법. 프로세스 내 경량 실행 단위.
- **Lec5 (프로세스 스케줄링)**: Ready → Running 결정 정책. PCB의 스케줄링 정보 활용.
- **Lec6 (동기화)**: Cooperating process의 공유 자원 접근 조율.
- **Lec7 (교착상태)**: 자원 할당 대기 순환.
