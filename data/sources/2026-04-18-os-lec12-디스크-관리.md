# OS Lec12 — 입출력 시스템 & 디스크 관리 (I/O System and Disk Management)

운영체제 강의 (2025 봄학기) **최종 12장**.

Lec11에서 file system의 논리적 구조를 다뤘다면, Lec12는 그 아래 **I/O HW 메커니즘과 disk 레벨 최적화**. 강의 로드맵(Lec2)에서 예고된 "I/O management" 섹션의 마무리. OS 전체 강의의 **종합장**.

## 요약

I/O HW는 Processor-controlled(**Polling**, **Interrupt**) 및 **DMA** 세 방식. OS는 I/O scheduling · Error handling · Device info 관리를 제공하며, **Buffering · Caching · Spooling**으로 성능 개선. **Disk scheduling**은 평가 3축(Throughput · Mean response time · **Predictability**) 하에 seek time 최적화 5종(**FCFS · SSTF · Scan · C-Scan · Look**) + rotational delay 최적화(**SLTF / Sector queueing**) + 통합(**SPTF** = Seek+Rotational delay)으로 분류. **RAID**는 복수 물리 disk를 하나의 논리 disk로 통합하여 성능·신뢰성 향상 — **RAID 0**(striping, 성능↑·신뢰성↓) · **RAID 1**(mirroring, 신뢰성↑) · **RAID 3**(byte+parity) · **RAID 4**(block+parity, 병목) · **RAID 5**(parity 분산, **현재 최다**).

## 핵심 포인트

### 1. I/O Mechanisms

#### (a) Processor Controlled Memory Access
- **Polling (programmed I/O)**: Processor가 주기적으로 I/O 장치 상태 확인.
  - 장점: Simple, I/O 빠르고 전송 잦을 때 효율적.
  - 단점: Processor 부담 큼, polling overhead(느린 I/O 경우).
- **Interrupt**: I/O 장치가 작업 완료 후 processor에게 상태 전달. Processor는 interrupt 발생 시 데이터 전송.
  - 장점: Low overhead, 불규칙 요청 처리 적합.
  - 단점: Interrupt handling overhead.

#### (b) Direct Memory Access (DMA)
- Processor controlled 방식의 **단점 해결** (processor가 모든 전송 처리 → high overhead).
- **I/O ↔ memory 전송을 processor 개입 없이 수행**.
- Processor는 데이터 전송의 **시작/종료만** 관여.
- DMA 제어기가 중재.

### 2. I/O Services of OS

OS 구조: Kernel → **Kernel I/O subsystem** → Device drivers → HW interface → Device controllers → Devices.

#### 핵심 서비스 3종
| 서비스 | 역할 |
|---|---|
| **I/O scheduling** | 입출력 요청 처리 순서 결정. 시스템 성능 향상, 공평성. 예) disk I/O scheduling. |
| **Error handling** | 입출력 중 오류 처리. 예) disk access fail, network error. |
| **I/O device info management** | 장치 정보 관리 |

#### 성능 개선 기법 3종
- **Buffering**: I/O ↔ Program 간 buffer에 임시 저장. **속도/처리 단위 차이 해결**.
- **Caching**: 자주 쓰는 데이터를 고속 디스크/메모리에 미리 복사. Cache hit 시 I/O 생략.
- **Spooling**: 한 I/O 장치에 여러 프로그램 요청 시 출력 섞임 방지. 각 프로그램별 disk file(spool)에 기록 후 한 번에 하나씩 장치로 전송. 예) 프린터.

### 3. Disk Scheduling — 평가 기준 3축

| 기준 | 의미 |
|---|---|
| **Throughput** | 단위 시간당 처리량 |
| **Mean response time** | 평균 응답 시간 |
| **Predictability** | 응답시간 예측 가능성. Starvation 방지 |

#### Data access time (Lec11 재확인)
Seek time + Rotational delay + Data transmission time.

### 4. Seek Time Optimizing 5종

**예시 설정**: 256 cylinder, head 시작 100, request queue = 160·200·90·170·20·190·120·130.

#### (a) FCFS (First Come First Service)
- 도착 순서대로. **Total seek distance = 690**.
- 장점: Simple, low scheduling overhead, 공평(starvation 없음).
- 단점: 성능 고려 없음.
- Disk 부하 적은 경우 적합.

#### (b) SSTF (Shortest Seek Time First)
- 현재 head에서 가장 가까운 요청. **Total = 300**.
- 장점: Throughput↑, 평균 응답시간↓.
- 단점: Predictability↓, **Starvation 가능**.
- 일괄 처리 시스템 적합.

#### (c) Scan (Elevator)
- 진행 방향에서 가까운 요청 먼저. 마지막 cylinder 도착 후 반대 방향. **Total = 300** (예시).
- 장점: SSTF starvation 해결, throughput·응답시간 우수.
- 단점: 진행 방향 반대 끝의 응답시간↑.

#### (d) C-Scan (Circular Scan)
- Head가 **한 방향으로만** 이동. 마지막 cylinder 도착 → 시작 cylinder로 이동 후 재시작.
- 장점: Scan 대비 **균등한 기회** 제공.
- (예시 seek distance = 490, 단 한 방향 이동 비용 포함).

#### (e) Look
- Scan/C-Scan의 **실제 구현**. 진행 방향에 요청이 없으면 방향 전환 (끝 cylinder까지 가지 않음).
- 장점: Scan의 불필요한 head 이동 제거. **Total = 260**.

### 5. Rotational Delay Optimizing

#### SLTF (Shortest Latency Time First) — Sector Queueing
- **Fixed head disk** (각 track마다 head, head 이동 없음. 예: drum disk) 용.
- 각 sector별 queue 유지.
- Head 아래 도착한 sector의 queue 요청 먼저 처리.
- **Moving head disk 응용**: 같은 cylinder 여러 요청 처리에 사용 가능. Cylinder 도착 → 고정 → 해당 cylinder 요청 모두 처리.

### 6. Positioning Time 통합

#### SPTF (Shortest Positioning Time First)
- **Positioning time = Seek time + Rotational delay**.
- Positioning time 가장 작은 요청 먼저.
- 장점: Throughput↑, 평균 응답시간↓.
- 단점: 가장 안/바깥 cylinder starvation 가능.

### 7. RAID Architecture

**RAID = Redundant Array of Independent (Inexpensive) Disks**.
- 여러 물리 disk를 하나의 논리 disk로.
- OS support 또는 RAID controller.
- 목적: **Performance** (access speed) + **Reliability**.

| Level | 방식 | 특징 |
|---|---|---|
| **RAID 0** | **Disk striping** (데이터 분할 분산) | Parallel access, 성능↑. 한 disk 고장 시 **데이터 손실**. Low reliability |
| **RAID 1** | **Disk mirroring** (2개 disk 중복) | 어느 disk에서도 I/O 가능. 한 disk 고장 OK. **High reliability**. 가용 용량 = 전체/2 |
| **RAID 3** | RAID 0 + **parity disk** (byte 단위) | Parallel access, 성능↑. Parity로 복구. Write 시 parity 계산 overhead, write 병목 가능 |
| **RAID 4** | RAID 3과 유사, **block 단위** 분산 | 독립적 access, disk 균등 분배 안될 수도. Parity disk 병목 |
| **RAID 5** | RAID 4 + **parity 분산 저장** | Parity disk 병목 해소. **현재 가장 널리 사용**. High performance + reliability |

기타: RAID 6, RAID 0+1 등 존재.

## OS 강의 전체 종료

이 Lec12가 **운영체제 강의 (2025 봄학기) 최종장**. Lec1(HW 기초)→Lec2(OS 개요)→Lec3-5(프로세스·스레드·스케줄링)→Lec6-7(동기화·교착상태)→Lec8-10(메모리·가상메모리)→Lec11-12(파일·I/O)로 이어지는 전체 OS 주제 완결.
