# OS Lec1 — 컴퓨터 시스템 개요

운영체제 강의 (2025 봄학기) 1장.

OS 본론에 앞서 **컴퓨터 하드웨어**(프로세서 · 메모리 · 주변장치)를 훑고, 각 HW 위에서 OS가 이후 장들에서 어떤 역할을 맡는지 포인터를 제시하는 **강의 전체 로드맵 장**.

## 요약

컴퓨터 하드웨어는 프로세서(CPU/GPU), 메모리(주·보조), 주변장치 3축으로 구성되며 **시스템 버스**(data·address·control)로 연결된다. **프로세서**는 Control Unit + Processing Unit(ALU) + Register로 이루어지고, 레지스터는 용도·가시성·정보 종류 3기준으로 분류된다(PC·IR·ACC·MAR·MBR·DR). 명령어 실행은 **PC→MAR→메모리→MBR→IR** 흐름의 fetch-execute 사이클로 진행된다. **메모리 계층**은 Register→Cache(HW 관리)→Main→Auxiliary(SW 관리)의 피라미드이며, **지역성**(공간적·시간적)이 캐시 적중률을 결정한다. 각 HW에 대응되는 **OS 역할**이 뒤 장의 로드맵으로 제시된다 — 프로세서는 3~5장, 메모리는 8~10장, 주변장치는 3·11·12장.

## 핵심 포인트

### 1. 컴퓨터 하드웨어 3요소

- **프로세서 (Processor)**: CPU, GPU 등. 연산 수행 + 모든 장치 동작 제어 ("컴퓨터의 두뇌").
- **메모리 (Memory)**: 주기억장치, 보조기억장치.
- **주변장치**: 키보드/마우스, 모니터/프린터, 네트워크 모뎀 등. 입력·출력·저장 장치로 분류.

### 2. 프로세서 내부 구조

- **Control Unit (제어장치)** + **Processing Unit (ALU)** + **Register**.
- Register는 프로세서 내부의 메모리 — 컴퓨터에서 **가장 빠른** 메모리.
- 레지스터 분류 3축:
  - **용도**: 전용 레지스터 / 범용 레지스터
  - **가시성**: 사용자 가시 / 불가시
  - **정보 종류**: 데이터 / 주소 / 상태 레지스터

### 3. 대표 레지스터

**사용자 가시**
- 데이터 레지스터 (data register) — 데이터 저장.
- 주소 레지스터 (address register) — 메모리 주소 저장 (베이스/스택/인덱스/세그먼트 포인터 등).

**사용자 불가시**
- **PC** (Program Counter) — 다음 실행할 명령의 메모리 주소.
- **IR** (Instruction Register) — 현재 실행 중 명령어.
- **ACC** (Accumulator) — 최근 산술/논리 연산 결과.
- **MAR** (Memory Address Register) — 접근할 데이터의 메모리 주소.
- **MBR** (Memory Buffer Register) — 입출력 작업 중 데이터. CPU와 I/O 속도 차 조정 버퍼.

### 4. 프로세서 동작 사이클 (예: `A = B + C + D`)

1. **Fetch 단계**: PC → MAR → 메모리 접근 → MBR → IR (다음 명령어 로드).
2. **Decode & Operand fetch**: 제어장치가 IR 명령어 해석 → 피연산자 주소 MAR로 → MBR로 데이터 → DR(Data Register) 저장.
3. **Execute**: ALU가 DR의 피연산자로 연산 → 결과 ACC에 저장.
4. 반복 (B, C, D 각각 fetch → 누적 합산).

### 5. OS와 프로세서의 연결

- 프로세서에 작업 할당 → [[프로세스]] 생성·관리 → **3장**
- 프로그램의 프로세서 사용 제어(시간 관리·조율) → **4장 (스레드)**, **5장 (스케줄링)**

### 6. 메모리 계층 (피라미드)

```
        [Register]           ← 속도 최고, 용량 최소
        [Cache]              ← HW 관리 경계
        ─────────────
        [Main Memory]        ← SW 관리 경계
        [Auxiliary Memory]   ← 속도 최저, 용량 최대
```

- **주기억장치 (Main memory)**: DRAM. 프로세서가 수행할 프로그램·데이터 저장. **디스크 I/O 병목 해소**.
- **캐시 (Cache)**: 프로세서 내부 (L1·L2·L3). HW 적으로 관리. **메인 메모리 I/O 병목 해소**.
  - Cache hit / Cache miss.
- **보조기억장치 (Auxiliary / secondary / storage)**: SSD·HDD·USB·ODD·카트리지 등. 프로세서가 직접 접근 불가 → 주기억장치 경유.
  - 프로그램 크기 > 주기억장치 → **가상 메모리 (Virtual memory)**.

### 7. 지역성 (Locality) — 캐시 적중률의 핵심

- **공간적 지역성 (Spatial locality)**: 참조 주소와 인접 주소를 참조. 예) 순차적 프로그램 실행, `a[i][j]` 행 우선 순회.
- **시간적 지역성 (Temporal locality)**: 한 번 참조한 주소를 곧 다시 참조. 예) for 루프 변수.
- `a[i][j]` (행 우선) vs `a[j][i]` (열 우선) 예제 — 행 우선이 캐시 친화적.
- "지역성은 캐시 적중률(cache hit ratio)과 밀접 → 알고리즘 성능 향상의 중요 요소."

### 8. OS와 메모리의 연결

- 메모리 할당·회수, 할당된 메모리 관리 → **8장**
- 가상 메모리 생성·관리, 논리→물리 주소 변환 → **9·10장**

### 9. 시스템 버스 (System Bus)

HW들이 데이터·신호를 주고받는 **물리적 통로**. 3종:

- **Data Bus**: 데이터 전송.
- **Address Bus**: 메모리/IO 주소 전달 (CPU가 읽기·쓰기 주소 송신).
- **Control Bus**: CPU·메모리·IO 간 제어 신호.

### 10. 주변장치와 OS

- **장치드라이버 관리**: 주변장치 사용 인터페이스 제공.
- **인터럽트 처리**: 주변장치의 요청 처리 → **3장**.
- **파일 및 디스크 관리**: 파일 생성/삭제, 디스크 공간 관리 → **11·12장**.

## 강의 로드맵 (이 강의 전체 매핑)

| HW | OS 역할 | 대응 장 |
|---|---|---|
| 프로세서 | 프로세스 생성·관리 | 3장 |
| 프로세서 | 스레드·스케줄링 | 4·5장 |
| 주변장치 | 인터럽트 | 3장 |
| 메모리 | 할당·관리 | 8장 |
| 메모리 | 가상 메모리 | 9·10장 |
| 주변장치 | 파일·디스크 | 11·12장 |

동기화(6장)·교착상태(7장)는 프로세서 관리 파트 후반에 배치 (본 강의 목차 순).
