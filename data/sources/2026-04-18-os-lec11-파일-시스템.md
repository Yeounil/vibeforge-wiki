# OS Lec11 — 파일 시스템 (File System)

운영체제 강의 (2025 봄학기) 11장.

Lec10까지 프로세스·메모리 관리를 다뤘다면, Lec11부터는 **I/O·저장장치 영역**. Disk system 기본 구조 소개 후 File system의 세 축(File · Directory · Partition) 및 protection·allocation·free space management를 커버. Disk system 자체는 Lec12에서 심화.

## 요약

File system은 file · directory · partition으로 구성되며, 사용자 파일을 관리하는 OS의 한 부분이다. **Disk**는 Sector/Track/Cylinder/Platter로 구성되며 데이터 접근시간은 **Seek + Rotational delay + Transmission**. **Directory 구조**는 Flat → 2-level(MFD/UFD) → **Hierarchical(tree, 대부분 OS)** → Acyclic graph(Unix symbolic link) → General graph(cycle + infinite loop 위험)로 발전. **File protection**은 **Access matrix**(Domain×Object, RWXA)로 formalize되며, 구현은 Global table · **Access list**(UNIX rwx) · **Capability list**(kernel 저장) · Lock-key 4종이 있고 실제 OS는 access+capability 혼용. **Allocation**은 **Continuous**(external frag) · **Linked/FAT**(MS-DOS·Windows, no external frag) · **Indexed**(Unix, index block per file)로 분류. **Free space**는 Bit vector · Linked list · Grouping · Counting으로 관리.

## 핵심 포인트

### 1. Disk System (Lec12 선행 개념)

#### Disk pack (비휘발성 저장장치)
| 구성 | 정의 |
|---|---|
| **Sector** | 물리적 데이터 저장/판독 단위 |
| **Track** | Platter 한 면의 같은 거리 sector 집합 |
| **Cylinder** | 같은 반지름을 갖는 track 집합 |
| **Platter** | 양면 자성 금속판 |
| **Surface** | Platter 윗면/아랫면 |

#### Disk drive 구성
- **Head** (기록/판독) · **Arm** (head 지탱) · **Positioner/boom** (arm 이동) · **Spindle** (회전축, **RPM**).

#### Data access time
1. **Seek time**: head → 필요한 cylinder 이동.
2. **Rotational delay**: 필요한 sector가 head 위치로 회전.
3. **Data transmission time**: sector 읽기/쓰기·전송.

#### Disk address
- **Physical**: `(Cylinder#, Surface#, Sector#)` 또는 `(Surface#, Cylinder#, Sector#)`.
- **Logical (relative)**: block들의 선형 나열 `B₀ B₁ B₂ …`. Block # → physical addr 변환 모듈 = **Disk driver**.
- 흐름: **OS (block#) → Disk driver (physical addr) → Disk controller**.

### 2. File System 개요

File system = 사용자 파일들을 관리하는 OS의 한 부분.

| 구성 | 역할 |
|---|---|
| **File** | 연관 정보의 집합 |
| **Directory structure** | 파일 정보 구성·제공 |
| **Partition** (minidisks, volumes, virtual disk) | Directory 집합을 논리/물리 구분 |

### 3. File Concept

- **정의**: 보조 기억 장치의 연관 정보 집합. 할당 최소 단위. 물리적으로 sequence of bytes.
- **분류**: 
  - 내용 — Program file (source/object/executable) · Data file.
  - 형태 — Text(ascii) · Binary.
- **Attributes (7)**: Name · Identifier · Type · Location · Size · Protection(access control) · User ID(owner) · Time(creation/last reference/last modification).
- **Operations**: Create · Write · Read · Reposition · Delete · Etc. → **OS가 system call 제공**.

#### File Access Methods
- **Sequential**: record/byte 순차 접근. 예) `fgetc()`.
- **Direct**: block 직접 접근. 예) `lseek()`, `seek()`.
- **Indexed**: index 참조 후 block 접근.

### 4. Directory Operations

- Search · Create · Delete · List · Rename · Traverse the file system.
- **Mounting**: 현재 file system에 다른 file system 붙이기 (mount point).

### 5. Directory Structure 5종 (진화 순)

#### (a) Flat (Single-level)
- 시스템 전체에 directory 1개. 다중 사용자 환경에서 naming·protection·management 모두 문제.

#### (b) 2-level
- 사용자마다 directory 1개. **MFD** (Master File Directory) + **UFD** (User File Directory).
- **문제**: Sub-directory 불가, 사용자간 공유 불가.

#### (c) Hierarchical (Tree) — **대부분 OS 채택**
- Tree 형태. 사용자가 sub-directory 생성·관리 가능 (system call 제공).
- Home directory, Current directory, **Absolute pathname**, **Relative pathname**.

#### (d) Acyclic Graph
- Hierarchical 확장. Shared directory/file 포함 가능.
- **Link** 개념 사용 → 예) **Unix symbolic link** (`ln -s`).

#### (e) General Graph
- Cycle 허용. **문제**: file 탐색 시 **infinite loop** 고려 필요.

### 6. File Protection

- 다중 사용자 환경에서 부적절한 접근 방지.
- **접근 제어 연산**: **R**(Read) · **W**(Write) · **X**(Execute) · **A**(Append).
- **기법 2종**:
  1. **Password**: 파일마다 PW → 비현실적 (사용자 암기 부담).
  2. **Access matrix**: Domain × Object 권한 명시.

### 7. Access Matrix

- **Object**: 접근 대상 (file·device 등 HW/SW).
- **Domain (protection domain)**: 같은 권한을 가진 그룹 (사용자·프로세스).
- **Access right**: `<object-name, rights-set>`.

|  | F1 | F2 | F3 | F4 | F5 |
|---|---|---|---|---|---|
| D1 | R | R |  | RW |  |
| D2 | RW |  |  | RA |  |
| D3 |  | R |  | RW | X |
| D4 | RW |  | X |  |  |

#### 4가지 구현

| 구현 | 방식 | 장·단점 |
|---|---|---|
| **Global table** | `<domain, object, rights>` 테이블 | Simple, 크기 큼 |
| **Access list** | Matrix의 **열(column)** = object별 권한 리스트. `Alist(Fk) = {<D1,R1>,…}` | **실제 OS 많이 사용 (UNIX rwx)**. Object별 권한 관리 쉬움. 매 접근 시 검사 → 많으면 느림 |
| **Capability list** | Matrix의 **행(row)** = domain별 권한 리스트. `Clist(D1) = {<F1,R1>,…}` | **Capability 소지 = 권한 소지**. Kernel이 보호. Localized 접근에 유리. 권한 취소 어려움 |
| **Lock-key** | Object에 lock, domain에 key (unique bit pattern). 짝 맞으면 접근 | Access + Capability 혼합. Kernel이 key list 관리 |

#### UNIX의 access list 예
```
rwx rwx rwx
(owner)(group)(universe)
```

#### 실제 OS: Access list + Capability list 혼용
1. 첫 접근 → **Access list 탐색** → 허용 시 **Capability 발급**.
2. 이후 접근은 권한 검사 불필요.
3. 마지막 접근 후 Capability 삭제.

### 8. Allocation Methods — File 저장 방식

#### (a) Continuous allocation
- 한 파일을 **연속된 block**에 저장.
- **장점**: 순차·직접 접근 효율적.
- **단점**: **External fragmentation**, 공간 확보 어려움, 파일 크기 사전 결정 필요.

#### (b) Linked allocation (Discontinuous)
- File block들을 **linked list**로 연결. Directory는 첫 block pointer만 보관.
- **장점**: 비연속 할당, simple, **no external fragmentation**.
- **단점**: 직접 접근 비효율, pointer 저장 공간, 신뢰성 (pointer 손상).
- **변형: FAT (File Allocation Table)** — 각 block 시작에 다음 block 번호 기록. **MS-DOS, Windows**.

#### (c) Indexed allocation
- 파일의 block pointer들을 **index block**에 모음.
- **장점**: 직접 접근 효율적.
- **단점**: 순차 접근 비효율, index block space overhead, index block 크기가 **파일 최대 크기 제한**.
- **Unix** 등에서 사용.

### 9. Free Space Management 4종

| 기법 | 방식 | 특징 |
|---|---|---|
| **Bit vector** | 모든 block을 1-bit flag로 표시 (0=free, 1=used) | Simple·efficient. 대형 시스템 부적합 (메모리 부담) |
| **Linked list** | 빈 block들을 linked list로 연결 | 비효율적 |
| **Grouping** | n개 빈 block을 그룹으로 묶고 그룹을 linked list로 | 연속 빈 block 찾기 쉬움 |
| **Counting** | `<시작 block, 연속 길이>` table | **Continuous allocation에 유리** |
