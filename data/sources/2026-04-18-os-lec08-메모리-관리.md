# OS Lec8 — 메모리 관리

운영체제 강의 (2025 봄학기) 8장.

Lec2의 OS 6대 기능 매핑에서 **Memory Management**에 해당. Lec1에서 본 메모리 계층을 기반으로, 프로세스가 공유하는 주기억장치를 어떻게 분할·할당할지 다룬다. **Continuous allocation** 전반 (Uni/FPM/VPM) 집중. Non-continuous (paging/segmentation)는 Lec9.

## 요약

주소는 **Logical (논리)**과 **Physical (물리)**로 구분되며, 둘의 매핑이 **Address Binding**이다. Binding 시점에 따라 Compile time (위치 고정) / Load time (재배치 가능, 전체 적재) / **Run time** (MMU 사용, 대부분 OS의 방식)으로 나뉜다. 프로그램 처리 단계는 Compiler → Linker → Loader로 이어지며, Dynamic Loading으로 필요 시점에만 루틴을 적재할 수 있다. 메모리 할당은 **Continuous**와 Non-continuous로 구분되며, Continuous 내에서 **Uni-programming** (degree=1, overlay·boundary register 도구)과 **Multi-programming** (FPM 고정 분할 vs **VPM** 동적 분할)으로 나뉜다. VPM은 internal fragmentation을 없애지만 external이 남아, **First-fit/Best-fit/Worst-fit/Next-fit** 배치 전략과 **Coalescing holes** / **Storage compaction** 통합 기법으로 대응한다.

## 핵심 포인트

### 1. 메모리 계층 (Lec1 심화)

| 계층 | 관리 | 단위 (다음 계층과) |
|---|---|---|
| Register | HW | Word (16–64 bits, 주기억↔레지스터) |
| Cache | HW | Cache line (주기억↔캐시) |
| Main memory | SW (OS) | Block (1–4 KB, 보조↔주기억) |
| Auxiliary storage | SW | — |

### 2. Physical vs Logical Address

- **Physical address**: HW 기억 공간에 부여된 실제 번호 (예: 0, 1, 2, ..., 63).
- **Logical address**: 논리 공간 상의 위치 이름 (예: 변수 `dataA`의 주소 = 0, 크기 = 2).
- 논리 주소는 Logical address space 상의 번호로, 물리 위치와 별도 관리.

### 3. Address Binding

프로그램의 논리 주소를 실제 메모리의 물리 주소로 매핑하는 작업.

| 시점 | 특징 | 전체 적재 |
|---|---|---|
| **Compile time binding** | 컴파일러가 메모리 위치를 앎. **위치 변경 불가** | 필요 |
| **Load time binding** | 대체 가능한 **상대 주소** 생성 → load 시 시작 주소 반영하여 재배치 | 필요 |
| **Run-time binding** (execution time binding) | Binding을 **수행 시간까지 연기**. 프로세스가 실행 중 이동 가능. **MMU (Memory Management Unit, HW)** 필요 | 불필요 |

- MMU: 논리 주소 + relocation register 값 = 물리 주소 (예: 256 + 10000 = 10256).
- **대부분 OS는 Run-time binding 사용**.

### 4. User Program 처리 단계

```
Source code → [Compiler] → Object module → [Linker] → Load module → [Loader] → In-memory binary Image
                             ↑ Other object       ↑ System lib     ↑ Dynamic loaded lib
──────── Compile time ────┤└──── Load time ────┤└── Run time ──
```

### 5. Dynamic Loading

- 모든 루틴을 교체 가능한 형태로 **디스크에 저장**.
- 메인 프로그램만 메모리에 적재, **실제 호출 시점에만** 루틴 적재.
- Binding은 호출 시점 수행.
- 장점: **메모리 공간 효율**.

### 6. Swapping

- Swap-out: 수행 완료 프로세스 → swap-device로 보냄 (Lec3의 suspended ready로 전이).
- Swap-in: 새 프로세스 메모리 적재 (resume).

### 7. Memory Allocation 분류

```
Continuous  ── 프로세스를 하나의 연속된 메모리 공간에 할당
├─ Uni-programming (degree=1)
└─ Multi-programming
   ├─ Fixed Partition Multi-programming (FPM, 고정 분할)
   └─ Variable Partition Multi-programming (VPM, 가변 분할)

Non-continuous (→ Lec9)
```

### 8. Uni-Programming

- **Multiprogramming degree = 1**. 단 하나의 프로세스만 메모리 상 존재.
- 구성: Kernel + User Program + Wasted Space.
- **가장 단순한 메모리 관리 기법**.

**문제와 해법**:

| 문제 | 해법 | 특징 |
|---|---|---|
| 프로그램 크기 > 메모리 크기 | **Overlay structure** — 필요한 영역만 적재 | 사용자가 흐름·자료구조 모두 알아야 함 |
| 커널(Kernel) 보호 | **Boundary register** — 경계 주소 저장 | 단순 HW 지원 |
| Low utilization, Low performance | **Multi-programming 전환** | degree > 1 |

### 9. Fixed Partition Multi-programming (FPM)

- 메모리 공간을 **고정 크기로 미리 분할**.
- 각 프로세스는 하나의 partition에 적재 (Process:Partition = 1:1).
- Partition 수 K → **Multiprogramming degree = K**.
- **Partition table (State table)**: partition ID · start address · size · current process ID · other fields.
- 보호: **여러 개의 Boundary register**.

**요약**:
- 고정 분할 → 관리 간편, **Low overhead**.
- **Internal fragmentation + External fragmentation 모두** 발생 → 시스템 자원 낭비.

### 10. Variable Partition Multi-programming (VPM)

- 초기에는 **전체가 하나의 영역**. 프로세스 처리 과정에서 **동적으로 분할**.
- **No internal fragmentation** (필요한 크기 정확히 할당).
- External fragmentation은 여전히 발생 가능.
- State table 크기·구성이 동적으로 변경.

**예시 흐름** (120 MB 메모리):

초기 → A(20)+100 → A+B(10)+90 → A+B+C(25)+65 → A+B+C+D(20)+45 → A+10(B exit)+C+D+45 → A+10+C+D+E(15)+30 → A+10+C+20(D exit)+E+30.

### 11. Placement Strategies (배치 전략)

VPM에서 어느 빈 partition에 프로세스를 넣을지 결정:

| 전략 | 선택 기준 | 장점 | 단점 |
|---|---|---|---|
| **First-fit** (최초 적합) | 충분한 크기의 **첫 번째** partition | Simple, low overhead | 공간 활용률 ↓ |
| **Best-fit** (최적 적합) | 들어갈 수 있는 **가장 작은** partition | 큰 partition 유지 | 전체 탐색, 작은 frag 다수 |
| **Worst-fit** (최악 적합) | 들어갈 수 있는 **가장 큰** partition | 작은 frag 감소 | 전체 탐색, 큰 프로세스 어려움 |
| **Next-fit** (순차 최초 적합) | First-fit + **마지막 위치부터** 탐색 | 사용 빈도 균등화, low overhead | — |

### 12. External Fragmentation 대응

#### (a) Coalescing Holes (공간 통합)
- **인접한 빈 영역**을 하나의 partition으로 통합.
- Process가 memory를 release할 때 수행.
- **Low overhead**.

#### (b) Storage Compaction (메모리 압축)
- **모든 빈 공간을 하나로 통합**.
- 적재 공간 확보가 필요할 때 수행.
- **High overhead**:
  - 모든 process **재배치** (process 중지 필요).
  - 많은 시스템 자원 소비.

### 13. Fragmentation 요약

| 유형 | 정의 | 발생 |
|---|---|---|
| **Internal fragmentation** | Partition 크기 > Process 크기 → partition 내부 낭비 | **FPM** |
| **External fragmentation** | 남은 총 메모리 ≥ 필요 크기지만 **연속 공간 부족** | **FPM · VPM** |

## 이어지는 Lec

- **Lec9 (가상 메모리)**: External fragmentation 문제의 근본 해결 — **Non-continuous allocation** (paging, segmentation). 또한 프로그램 크기 > 메모리 문제도 해결.
