# OS Lec2 — 운영체제 개요

운영체제 강의 (2025 봄학기) 2장.

**강의 전체의 개념 허브**. OS의 역할·구분(3축)·역사적 진화·구조·6대 기능을 한 번에 훑는다. 여기서 처음 등장하는 거의 모든 용어가 후속 장에서 본격 심화됨.

## 요약

운영체제는 사용자-HW 사이 시스템 SW로, **3대 역할**(User Interface·Resource Management·System Management)을 수행한다. 동시 사용자 수·동시 프로세스 수·작업 수행 방식 **3축**으로 구분되며, 작업 방식에 따라 No-OS→Batch→Time-sharing→Personal computing→Parallel/Distributed/Real-time으로 역사적 진화를 거쳤다. 구조는 **Kernel + Utility** 조합이며, 응용은 **System Call**을 통해서만 커널에 접근한다. Kernel 설계는 **단일·계층·마이크로 커널** 3가지. 주요 기능은 Process·Processor·Memory·File·I/O 관리와 기타(Disk·Network·Security·Command interpreter·System call)로 나뉘며, 이 목록이 **이 강의의 이후 장 매핑과 정확히 일치**한다.

## 핵심 포인트

### 1. OS의 3대 역할

| 역할 | 관점 | 세부 |
|---|---|---|
| **User Interface** | 편리성 | CUI (Character) / GUI (Graphical) / EUCI (End-User Comfortable, 예: 세탁기 패널) |
| **Resource Management** | 효율성 | HW resource (processor·memory·I/O) + SW resource (file·application·message·signal) + process/thread |
| **System Management** | 시스템 보호 | 보안·접근 제어·권한 |

### 2. OS 구분 3축

- **동시 사용자 수**:
  - *Single-user*: 1명 독점. 개인용 (Windows 10/11, Android, MS-DOS).
  - *Multi-user*: 동시 사용. 자원 소유 권한 관리 필요. 다중작업 기반. 복잡 (Unix, Linux, Windows Server).
- **동시 실행 프로세스 수**:
  - *Single-tasking*: 한 번에 한 프로세스만 (MS-DOS).
  - *Multi-tasking* (= multiprogramming): 동기화 관리 필요 (Unix/Linux, Windows).
- **작업 수행 방식** (사용자가 느끼는 환경): Batch / Time-sharing / Distributed / Real-time → 아래 섹션에서 상세.

### 3. OS 역사적 진화 (작업 수행 방식 중심)

| 시대 | 방식 | 특징 |
|---|---|---|
| ~1940s | **순차 처리 (No OS)** | 기계어 직접. 모든 제어를 프로그램에 포함. 작업당 준비시간. |
| 1950s~60s | **Batch systems** | 중앙 전자계산소, 천공카드 일괄. **시스템 지향**. throughput↑, 생산성↓, turnaround ~**6시간**. |
| 1960s~70s | **Time-sharing** | 여러 사용자 동시 사용 (CRT terminal, 대화형). OS가 파일 시스템·가상 메모리 관리. **사용자 지향**. response ~**5초**. 단점: 통신비·체감속도. |
| 1970s~80s | **Personal computing** | 개인 독점. CPU 활용률 무관. OS 단순. 응답 빠름, 성능 낮음 (Apple II 1977). |
| — | **Parallel processing** | 단일 시스템 내 다중 프로세서. 자원 공유 (**tightly-coupled**). 성능·신뢰성. |
| — | **Distributed processing** | 네트워크 기반 병렬 (**loosely-coupled**). 분산운영체제가 하나처럼 제공 (**은폐성/transparency**). Cluster·C/S·P2P. 장점 성능·고신뢰성·확장성 / 단점 구축·관리 어려움. |
| — | **Real-time systems** | **Deadline** 중심. 자원 효율보다 시한 준수가 우선. Hard (발전소·무기), Soft (동영상), Non real-time. |

### 4. OS 구조 = Kernel + Utility

- **Kernel**: OS 핵심부. **메모리 상주**. 빈번히 쓰이는 시스템 관리 기능.
  - 동의어: **핵(nucleus)**, **관리자(supervisor)**, **상주(resident)**, **제어(control) 프로그램**.
- **Utility**: **비상주** 프로그램. UI·서비스 프로그램.
- **계층**: `Applications` → `Utilities / System SW` → **System Call Interface** → **Kernel** (Resource Management) → `Hardware`.

### 5. System Call

- 커널 기능 중 응용이 사용하도록 **허락된 기능 집합**.
- 커널 기능에 접근하는 **유일한 통로 인터페이스** (은행 창구 비유).

### 6. 커널 3가지 설계 구조

| 구조 | 장점 | 단점 |
|---|---|---|
| **단일 (Monolithic)** | 모듈간 직접 통신, 효율적 자원 관리 | 거대화, 유지보수 난, 한 모듈 문제→전체 영향 (악성 코드 등) |
| **계층 (Layered)** | 모듈화, 검증·수정 쉬움, 설계 단순 | 계층 경유 오버헤드로 성능 저하 |
| **마이크로 커널** | 커널 최소화. 필수 기능만 커널, 나머지는 사용자 영역 (파일시스템·장치·네트워크) | (슬라이드에 단점 명시 없음, 보통 IPC 오버헤드로 알려짐) |

### 7. OS 6대 기능 = 이후 강의 매핑

| 기능 | 상세 | 대응 장 |
|---|---|---|
| **Process management** | 생성/삭제/상태·자원 할당·프로세스 간 통신/동기화·**교착상태 해결**·**PCB (Process Control Block)** 관리 | 3·6·7장 |
| **Processor management** | CPU 프로그램 실행 핵심 자원. **프로세스 스케줄링**·할당 관리 (한 번에 1 프로세스) | 4·5장 |
| **Memory management** | Multi-user/tasking에서 할당·회수·여유 관리·**영역 접근 보호**. 할당 방식 2종: *전체 적재* (간단·공간 제한) / *일부 적재* = **virtual memory concept** (효율·보조기억 접근 필요) | 8·9·10장 |
| **File management** | 파일(논리 저장 단위)·디렉토리 구조·파일 접근·물리 저장공간 **매핑(mapping)**·백업 | 11장 |
| **I/O management** | 모든 I/O는 **OS를 반드시 경유**. 프로세스→OS→입출력 처리장치→인터럽트로 완료. 커널 공간에 IOCS·입출력 버퍼 | 12장 (+ 3장 인터럽트) |
| **기타** | Disk, Networking, Security & protection, Command interpreter, System call interface | — |
