# DB 4주차 — 제약조건 & 데이터 모델링

DB 강의 (2026 봄학기)의 4주차. ⑦ [[관계형 데이터 모델]]의 제약조건(키·무결성), ⑧ 데이터 모델링 개요와 3단계 모델링.

## 강의 7 — 관계형 데이터베이스의 제약조건

### 1. 키(Key) 개념

[[릴레이션]]은 튜플 집합이므로 각 튜플은 서로 다름. 전체 속성을 쓰면 항상 식별 가능하지만, 일반적으로 **일부 속성만으로** 튜플을 유일 식별 가능.

**기본 성질 2가지**
- **유일성(Uniqueness)** — 서로 다른 두 튜플의 키 값이 같지 않음
- **최소성(Minimality)** — 식별에 필요한 **최소한의 속성**만 포함

### 2. 키의 종류

| 키 | 유일성 | 최소성 | 설명 |
|---|---|---|---|
| **수퍼키 (Superkey)** | O | × | 튜플 유일 식별 가능한 모든 속성 집합 |
| **후보키 (Candidate Key)** | O | O | 유일성·최소성 만족. 수퍼키의 부분집합 |
| **기본키 (Primary Key, PK)** | O | O | DBA가 지정한 **하나의** 후보키. 관계형 DB의 기본 접근 방법 |
| **대체키 (Alternate Key)** | O | O | 후보키 중 기본키를 제외한 나머지 |
| **외래키 (Foreign Key, FK)** | | | 다른 릴레이션의 **기본키를 참조**하는 속성 |

**예**: `학생(학번, 이름, 주민번호)` → 후보키 {학번, 주민번호}, 기본키 {학번}, 대체키 {주민번호}.

### 3. 외래키

`R1(참조)`의 속성 FK의 도메인이 `R2(피참조)`의 **기본키**일 때, FK는 R1의 외래키.

R1 = R2일 수도 있음 (자기 참조) — 예: `사원(사번, 이름, 관리자)`의 `관리자`는 같은 테이블의 `사번`을 참조.

### 4. 무결성 제약조건 3종

데이터 모델의 3요소 중 **제약조건(Constraint)** 에 해당.

| 제약 | 정의 |
|---|---|
| **개체 무결성** (Entity Integrity) | 기본키 값은 **NULL 불가**. 식별자 없으면 개체 정의에 모순. |
| **참조 무결성** (Referential Integrity) | 외래키 값은 피참조 릴레이션의 **기본키 값** 혹은 **NULL**. 추가 제약으로 NULL 불가 지정 가능. |
| **도메인 무결성** (Domain Integrity) | 속성 값은 해당 도메인 내의 값이어야 함. |

DBMS는 상태 변이마다 제약을 자동 검사·유지.

### 5. 갱신 연산과 제약 처리

- **삽입(Insert)** — 도메인/기본키/참조 제약 위반 시 거부 또는 경고.
- **삭제(Delete)** — 참조 제약 위반 시 3 옵션:
  1. **삭제 거부**
  2. **연쇄 삭제(Cascade)** — 참조 튜플도 모두 삭제
  3. **NULL로 치환 또는 다른 유효 튜플 참조**
- **수정(Update)** — 기본적으로 "삭제 후 삽입"이므로 위 문제 모두 발생. 비-키 속성 변경은 문제없음.

## 강의 8 — 데이터 모델링

### 1. 3중 세계관

| 세계 | 대응 |
|---|---|
| **실세계** | 개체(Entity) — 사람·장소·물건·사건·개념 |
| **개념 세계** | 개체 타입(추상화) |
| **컴퓨터 세계** | 레코드(튜플) — 논리적 구조 |

실세계 → (**추상화**) → 개념 세계 → (**모델링**) → 컴퓨터 세계.

### 2. 데이터 모델링 정의

복잡한 현실 세계를 **일정한 표기법**에 따라 **추상화·단순화·명확화**하여 표현하는 기법.

- 정보 공학(Information Engineering) 기반.
- 관점 2축: **데이터 관점(What)** vs **프로세스 관점(How)**.
- 정보 공학 모델링은 데이터·프로세스 **분리**, 객체 지향은 **동시** 모델링.

### 3. 데이터 모델의 중요성

- **파급효과** — 구축 중 데이터 구조 변경은 전체 프로젝트의 위험 요소.
- **간결한 표현** — 수많은 페이지의 기능 요구보다 데이터 모델 리뷰가 빠름.
- **데이터 품질** — 기업 자산. 기간이 오래될수록 가치 상승.

### 4. 데이터 모델링 유의점

- **중복(Duplication)** — 사용자·시간·장소 파악 어려움.
- **비유연성(Inflexibility)** — 데이터 정의와 사용 프로세스를 분리해야 함.
- **비일관성(Inconsistency)** — 중복 없어도 발생 가능. 데이터 간 연관 정의로 예방.

### 5. 좋은 데이터 모델 조건

**완전성 · 중복 배제 · 데이터 재사용 · 업무 규칙 · 안정성·확장성 · 간결성 · 의사소통 · 통합성**.

### 6. 3단계 데이터 모델링

| 단계 | 특징 | 대응 프로젝트 단계 |
|---|---|---|
| **개념 데이터 모델링** | 추상화 수준 높음, 핵심 개체·관계 도출, **ERD 작성** | 계획/분석 |
| **논리 데이터 모델링** | 개념 모델 상세화, 속성·식별자 확정, **정규화** | 분석 |
| **물리 데이터 모델링** | 대상 DBMS 고려, 칼럼 타입·크기, **인덱스·역정규화** | 설계 |

**개념 모델링 ≠ 개괄·추상 모델**. 주요 개체·식별자·관계가 모두 도출된 구체적 모델.

### 7. 데이터 독립성 복습

ANSI [[3단계 스키마]] (외부·개념·내부) 재확인.

- **논리적 독립성** — 개념 스키마 변경 → 외부 스키마·응용 영향 없음
- **물리적 독립성** — 내부 스키마 변경 → 개념·외부 영향 없음

→ [[데이터 독립성]] 참조.

## 핵심 용어

| 용어 | 정의 |
|---|---|
| 수퍼키 | 유일성만 만족 |
| 후보키 | 유일성 + 최소성 만족 |
| 기본키(PK) | 지정된 후보키. NULL 불가 |
| 대체키 | 선택되지 않은 후보키 |
| 외래키(FK) | 다른 릴레이션 기본키 참조 |
| 개체 무결성 | PK NOT NULL |
| 참조 무결성 | FK는 피참조 PK 값 또는 NULL |
| 도메인 무결성 | 속성 값은 도메인 내 |
| 개념·논리·물리 모델링 | 3단계 모델링 |
