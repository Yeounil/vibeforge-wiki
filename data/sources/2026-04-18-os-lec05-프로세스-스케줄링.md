# OS Lec5 — 프로세스 스케줄링

운영체제 강의 (2025 봄학기) 5장.

Lec3에서 예고된 **프로세서 사용 시간 분배**의 본격 다루기. 시스템 성능 지표·스케줄링 3단계·정책·7대 기본 알고리즘·Unix/Windows 사례까지, 이 강의에서 가장 밀도 높은 장.

## 요약

Multi-programming 환경에서는 자원 할당 프로세스 선택이 필연적이다. 스케줄링은 **시간 분할**(CPU)과 **공간 분할**(메모리)로 구분되며, 성능은 평균 RT·throughput·utilization·fairness 등으로 측정된다. 발생 빈도에 따라 **Long-term**(Job admission) → **Mid-term**(메모리 swapping) → **Short-term**(Process dispatcher) 3단계로 나뉜다. 정책은 **Preemptive/Non-preemptive**와 **Static/Dynamic priority** 축으로 구성된다. 7대 기본 알고리즘 — **FCFS·RR**(fairness 축), **SPN·SRTN·HRRN**(efficiency 축), **MLQ·MFQ**(종합) — 각각 기준·장단점·starvation 여부가 명확히 대비된다. 사례 연구로 Unix의 decay computation 기반 동적 우선순위와 Windows의 32-level thread scheduling을 다룬다.

## 핵심 포인트

### 1. Multi-programming과 자원 관리

- **여러 프로세스 공존** → 자원 할당 프로세스 **선택 = 스케줄링**.
- **시간 분할**(time sharing): 하나의 자원을 번갈아 사용. 예) processor → **프로세스 스케줄링**.
- **공간 분할**(space sharing): 하나의 자원을 분할해 동시 사용. 예) memory.

### 2. 스케줄링 목적 · 성능 지표

| 지표 | 의미 |
|---|---|
| **평균 응답 시간 (mean RT)** | 사용자 지향 (interactive) |
| **Throughput** | 단위 시간당 완료 작업 수. 시스템 지향 (batch) |
| **Resource utilization** | Tr/Tc. 자원이 활용된 비율 |
| **Fairness** | 자원 할당 공정성. FIFO |
| **실행 대기 방지** | 무기한 대기(starvation) 방지 |
| **Predictability** | 적절 시간 내 응답 보장 |

기타: overhead 최소화, 균형 유지, 우선순위, 서비스 기회 확대.

### 3. 시간 용어 (공식)

- **BT** (Burst Time): 실행 시간 (CPU 사용 시간).
- **WT** (Waiting Time) = **TT − BT**.
- **TT** (Turn-around Time): 도착~종료.
- **RT** (Response Time): 도착~첫 출력.
- **NTT** (Normalized TT) = **TT / BT**.

### 4. CPU burst vs I/O burst

- 프로세스 수행 = CPU 사용 + I/O 대기.
- **Compute-bound (CPU burst ≫)**: 계산 많은 프로세스.
- **I/O-bound (I/O burst ≫)**: 입출력 많은 프로세스.
- Burst time은 스케줄링 핵심 기준.

### 5. 스케줄링 기준 (Criteria)

- 프로세스 특성: I/O-bounded / compute-bounded
- 시스템 특성: Batch / Interactive
- 긴급성: Hard / Soft / Non real-time
- 우선순위 (priority)
- 프로세스 총 실행 시간 (total service time)

### 6. 스케줄링 3단계 (Level)

| 단계 | 별칭 | 대상 | 빈도 |
|---|---|---|---|
| **Long-term** | Job scheduling, Admission, High-level | 시스템 등록 결정. 다중 프로그래밍 degree 조절, I/O·compute 믹스. 시분할 시스템에선 덜 중요 | 낮음 |
| **Mid-term** | Intermediate-level | 메모리 할당. **Swapping** (swap-in/swap-out) | 중간 |
| **Short-term** | Process scheduling, Low-level, **Dispatcher** | Processor → Process 결정. Interrupt·block·time-out 시 발생. **가장 빈번·빨라야 함** | 매우 높음 |

*예시*: 평균 CPU burst 100ms + scheduling decision 10ms → 약 9%의 CPU가 스케줄링에 소비.

상태 전이 다이어그램과 매핑: Long-term → created 진입, Mid-term → active↔suspended, Short-term → ready→running.

### 7. 스케줄링 정책 (Policy)

#### (a) Preemptive vs Non-preemptive

| 구분 | Non-preemptive | Preemptive |
|---|---|---|
| 반납 | 자발 반납 | 타의로 빼앗김 |
| 예 | system call, I/O | 높은 priority 등장 |
| 장점 | Context switch overhead 적음 | 응답성 향상 |
| 단점 | 우선순위 역전, RT 증가 | Context switch overhead 큼 |
| 적합 | batch | time-sharing, real-time |

#### (b) Priority (우선순위)

- **Static priority**: 생성 시 결정. 단순·저overhead / 환경 변화 대응 어려움.
- **Dynamic priority**: 상태 변화에 따라 변경. 유연 / 재계산 overhead.

### 8. 기본 스케줄링 알고리즘 7종

#### FCFS (First-Come-First-Service)

- **Non-preemptive**. 도착 시간 기준 (ready queue).
- 자원 효율적 사용 (high utilization). Batch 적합, interactive 부적합.
- **단점**:
  - **Convoy effect (호위 효과)**: 긴 프로세스 뒤 대기 (WT ≫ BT).
  - 긴 평균 RT.

#### RR (Round-Robin)

- **Preemptive**. 도착 시간 + **time quantum (δ)** (system parameter).
- **Timer-runout**으로 반납 → 독점(monopoly) 방지.
- **Context switch overhead 큼**. 대화형·시분할 적합.
- δ 영향:
  - Very large (∞) δ → **FCFS**.
  - Very small δ → **processor sharing** (사용자 체감 = 실제 성능의 1/n, overhead 폭증).

#### SPN (Shortest-Process-Next = SJF)

- **Non-preemptive**. **Burst time** 최소 프로세스 우선.
- **장점**: **평균 WT 최소**, 시스템 내 프로세스 수 최소, 빠른 RT.
- **단점**:
  - **Starvation** (BT 긴 프로세스 무한 대기) → **Aging** (예: HRRN)으로 해결.
  - 정확한 실행 시간 예측 필요.

#### SRTN (Shortest Remaining Time Next)

- SPN의 **Preemptive** 변형. 잔여 시간 더 짧은 프로세스 ready 시 선점.
- **장점**: SPN 극대화.
- **단점**: 잔여 시간 계속 추적 + context switch overhead → **구현·사용 비현실적**.

#### HRRN (Highest Response-Ratio-Next)

- **Non-preemptive**. **SPN + aging concepts**.
- **Response ratio = (WT + BT) / BT** (응답 비율).
- 대기 시간이 긴 프로세스에 기회 → **Starvation 방지 + SPN 장점**.
- 단점: 실행 시간 예측 필요.

#### MLQ (Multi-Level Queue)

- 작업/우선순위별 **별도 ready queue**. 최초 배정된 큐 **이탈 불가**.
- 각 큐는 자신의 스케줄링 기법 사용. 큐 간: **fixed-priority preemptive**.
- **장점**: 높은 priority 빠른 응답, 낮은 priority 스케줄링 부하 감소.
- **단점**: 큐 관리 overhead, 낮은 priority **starvation** 가능.

#### MFQ (Multi-level Feedback Queue)

- **큐 간 이동 허용**된 MLQ. **Feedback으로 우선순위 조정** (프로세서 사용 패턴 활용).
- 특성: **Dynamic priority**, Preemptive, short burst 우대, I/O-bound 우대, adaptability.
- → **사전 정보 없이 SPN/SRTN/HRRN의 효과**.
- 변형:
  - 큐별 time quantum 다르게 배정
  - I/O 위주 프로세스 상위 큐로 이동 → 평균 RT 감소, I/O 분산
  - 대기 지정 시간 초과 시 상위 큐로 이동 → **Aging 기법**
- 파라미터: 큐 수, 큐별 알고리즘, 우선순위 조정 기준, 최초 배정 방법.

### 9. 알고리즘 분류 축

```
Fairness (공평성)        ↔       Efficiency/Performance (효율성)
  FCFS, RR                        SPN, SRTN, HRRN
         ↓                                    ↓
     [문제: 실행시간 예측 부하]
         ↓                                    ↓
              MLQ, MFQ (종합 해결)
```

### 10. Case Study

#### Scheduling in Unix

- Interactive system, **Priority-based + Preemptive**. **MFQ 기반**.
- **Kernel priority** (0–59): 커널 모드 — uninterruptible / interruptible.
- **User priority** (60–119): 사용자 모드.
- **Threshold priority**로 경계 분리.
- **Clock handler**: 주기적 interrupt → 모든 프로세스 우선순위 조정.
- **Decay computation**:
  - `CPUCount = CPUCount / 2`
  - `Priority = CPUCount/2 + basePriority + niceValue`
  - (`niceValue`: 사용자가 설정 가능한 우선순위 조정값, Unix `nice` 명령)

#### Scheduling in Windows

- **Thread scheduling** (프로세스가 아닌 스레드). Priority-based + Preemptive. **MFQ**.
- **32-level priority scheme**:
  - **Variable class**: 1–15 (일반 응용).
  - **Real-time class**: 16–32.
- Priority class × Priority level 매트릭스 — 예) Normal class + normal priority = 8.
- 스케줄링 기법:
  - Time quantum 소진 → **하향 조정** (variable class).
  - **Wake-up** → **상향 조정** (대기 작업 종류에 따라):
    - 키보드/마우스 I/O → **크게** 상향
    - 디스크 I/O → 약간 상향
