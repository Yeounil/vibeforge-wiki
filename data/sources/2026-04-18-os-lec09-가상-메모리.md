# OS Lec9 — 가상 메모리 (Non-continuous Allocation)

운영체제 강의 (2025 봄학기) 9장.

Lec8의 Continuous allocation에서 미뤘던 **Non-continuous allocation** 본격. Lec1의 가상 메모리 개념, Lec2의 메모리 관리 로드맵에서 9·10장으로 예고된 주제. Lec10(가상 메모리 관리)에서 page replacement 등으로 심화.

## 요약

Non-continuous allocation은 프로그램을 여러 block으로 분할하여 필요한 block만 메모리에 적재하고 나머지는 swap device에 두는 방식으로, 프로세스는 연속 적재를 착각하지만 실제는 불연속이다 (address mapping으로 은폐). Virtual address `v = (b, d)` → BMT 조회 → real address `r = a + d`가 기본 block mapping 모델. 기법은 3가지 — **Paging**(고정 크기 page/page frame, PMT, **No external frag**), **Segmentation**(논리적 분할 segment, SMT, No internal frag, sharing 용이), **Hybrid**(둘의 결합, SMT + segment별 PMT, 메모리 접근 3배). Paging의 address mapping은 Direct / Associative(**TLB**) / Hybrid 3종으로 발전하며, 후자는 Lec1의 **locality** 개념을 활용한다.

## 핵심 포인트

### 1. Non-continuous Allocation 기본 개념

- 사용자 프로그램을 여러 **block**으로 분할.
- 실행 시 **필요한 block만 메모리에 적재**, 나머지는 **swap device**.
- 프로세스 관점: 가상메모리 (연속 적재 가정). 실제: 분산 적재.
- 기법:
  - **Paging system**
  - **Segmentation system**
  - **Hybrid paging/segmentation system**

### 2. 주소 용어 (Lec8 심화)

| 용어 | 의미 |
|---|---|
| **Virtual address** (= Logical, Relative) | 연속 메모리 할당을 가정한 주소 |
| **Real address** (= Absolute, Physical) | 실제 메모리에 적재된 주소 |
| **Address mapping** | Virtual → Real 변환 |

### 3. Block Mapping (일반 모델)

- Virtual address: `v = (b, d)`
  - `b`: block number
  - `d`: displacement (offset in block)
- **BMT (Block Map Table)**:
  - 커널 공간, 프로세스마다 하나.
  - Columns: block number · **residence bit** · ... · real address.
- 절차:
  1. BMT 접근.
  2. Block b entry 탐색.
  3. Residence bit 검사:
     - 0: swap device → 메모리 적재 + BMT 갱신 → ②로.
     - 1: real address `a` 확인.
  4. `r = a + d` 계산.
  5. `r`로 메모리 접근.

### 4. Paging System — 개념

- 프로그램을 **같은 크기**의 블록 = **Page**로 분할.
- 메모리도 **같은 크기**의 **Page frame**으로 분할 (FPM 유사).
- Windows: page size = **4 KB** (시스템마다 다름).

**특징**:
- **논리적 분할 아님** (크기 기반).
- Page sharing/protection **복잡** (Segmentation 대비).
- **Simple and efficient** (Segmentation 대비).
- **No external fragmentation** / Internal fragmentation 가능.

### 5. Paging Address Mapping

- Virtual address: `v = (p, d)` — page number + displacement.
- **PMT (Page Map Table)**:
  - Columns: page number · residence bit · secondary storage address · other fields · **page frame number**.

**3가지 Mapping Mechanism**:

#### (a) Direct Mapping
- PMT를 커널 메모리에 저장.
- 절차: `b + p * entrySize` → PMT entry → residence 검사 → `r = p' * pageSize + d`.
- **메모리 접근 2배** (PMT 1회 + data 1회).
- **Page fault** (residence=0): swap 수행, context switching → overhead.
- **단점**: 성능 저하, PMT 공간.

#### (b) Associative Mapping (TLB)
- **TLB (Translation Look-aside Buffer)** — associative high-speed memory.
- PMT를 **병렬 탐색**.
- **Low overhead, high speed**.
- **단점**: Expensive hardware, 큰 PMT 다루기 어려움.
- Typical TLB: 12 bits–4,096 entries, hit time 0.5–1 cycle, miss penalty 10–100 cycles, miss rate 0.01–1% (20–40% for sparse/graph apps).

#### (c) Hybrid Direct/Associative Mapping
- 작은 TLB에 **PMT 일부 entry** (최근 사용) 저장. 나머지 PMT는 커널 메모리.
- 절차: TLB 확인 (hit → 바로 page frame) / miss → direct mapping + TLB 갱신.
- **Locality 활용** (Lec1 재등장):
  - **Temporal locality** (시간적): 한 번 접근 → 곧 다시 접근.
  - **Spatial locality** (공간적): 인접 주소 재접근.
- HW 비용 ↓, associative 장점 유지.

### 6. Paging Memory Management

- **Frame table**: page frame당 entry.
  - **Allocated / available field**
  - **PID field** (process ID)
  - **Link field**: free list 연결용.
- **AV (Available)**: free list 헤더.

### 7. Page Sharing

Non-continuous allocation 덕에 여러 프로세스가 특정 page를 공유 가능.

**공유 가능 Page**:
- **Procedure pages**: **Pure code** (재진입 가능).
- **Data pages**: Read-only data / Read-write data (**concurrency 제어 하에서만** 가능).

**예**: Editor 프로그램을 3 프로세스가 공유 → Code1/Code2/Code3 page frame을 공유, Data만 별도.

**Procedure Page Sharing Problem**:
- 프로세스 P1·P2가 다른 page entry 번호(k1·k2)로 접근 시 `Branch(?, d)` 내부 주소 혼란.
- **Solution**: 프로세스들이 **같은 entry number `k`** 사용 → `Branch(k, d)` 통일.

### 8. Page Protection

- **Protection bit** (RWE):
  - **R** (Read)
  - **W** (Write)
  - **E** (Execution)
- PMT entry에 저장. 접근 시 검사.

### 9. Segmentation System

- 프로그램을 **논리적 block** = **Segment**로 분할 (stack, heap, main procedure, shared lib 등).
- Segment 크기 **다를 수 있음**.

**특징**:
- 메모리 미리 분할 X (**VPM 유사**).
- **Segment sharing/protection 용이** (논리 단위라서).
- Address mapping / 메모리 관리 **overhead 큼** (Paging 대비).
- **No internal fragmentation** / External fragmentation 가능.

### 10. Segmentation Address Mapping

- Virtual address: `v = (s, d)` — segment number + displacement.
- **SMT (Segment Map Table)**:
  - Columns: segment# · residence bit · secondary storage address · **segment length (l)** · **protection bits (R/W/X/A)** · ... · **segment address**.
- Direct mapping 절차 + 3가지 예외:
  1. **Segment fault** (residence=0): swap device에서 segment 적재, SMT 갱신.
  2. **Segment overflow** (d > l_s): segment overflow exception.
  3. **Segment protection** (RWE 위반): segment protection exception.
- `r = a_s + d`.

**메모리 관리**: VPM 유사. Segment 적재 시 크기에 맞춰 분할 후 적재. Partition table에 `segment number` + `storage protection key` 포함.

### 11. Paging vs Segmentation 비교

| 항목 | Paging | Segmentation |
|---|---|---|
| 분할 기준 | 고정 크기 | 논리적 (가변) |
| Management | Simple, **low overhead** | **High overhead** |
| Logical partitioning | ✗ | ✓ |
| Sharing mechanism | **Complex** | **Simple, easy** |
| Internal fragmentation | **있음** | 없음 |
| External fragmentation | 없음 | **있음** |

### 12. Hybrid Paging/Segmentation System

**원리**: 두 기법의 장점 결합.

- 프로그램 분할:
  1. 논리 단위 segment로 분할.
  2. 각 segment를 고정 크기 page들로 분할.
- **Page 단위로 메모리 적재**.

**Address mapping**:
- Virtual address: `v = (s, p, d)` — segment + page + displacement.
- 테이블:
  - **SMT** (프로세스마다 1개): segment length · protection bits · **PMT address**. **Residence bit 없음** (PMT에만).
  - **PMT** (각 segment마다 1개): residence bit · secondary storage address · page frame number.
- Direct mapping: SMT entry (`b + s * SMTentrySize`) → PMT entry (`b_s + p * PMTentrySize`) → memory (`p' * pageSize + d`).
- **메모리 접근 3배** (SMT + PMT + data).

**특징**:
- 장점: Page sharing/protection 쉬움, 메모리 할당/관리 overhead 작음, **no external fragmentation**.
- 단점: 전체 테이블 수 증가 → 메모리 소모 ↑, mapping 복잡, 성능 저하 가능.
