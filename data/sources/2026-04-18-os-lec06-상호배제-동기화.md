# OS Lec6 — 프로세스 동기화 & 상호배제

운영체제 강의 (2025 봄학기) 6장.

Lec3에서 소개된 **프로세스 간 상호작용**(cooperating process)의 본격 다루기. **Race condition**을 해소하는 전 스펙트럼의 상호배제 기법을 SW·HW·OS 지원·언어 레벨로 계층화해 다룬다.

## 요약

Multi-programming 환경에서 비동기적·병행적 프로세스들이 공유 자원에 동시 접근하면 **race condition**이 발생한다. 이를 해결하려면 공유 데이터(critical data)를 접근하는 **임계 영역(Critical section, CS)**에 한 번에 한 프로세스만 진입하도록 **상호배제(Mutual exclusion)**를 보장해야 한다. ME primitive는 **Mutual exclusion·Progress·Bounded waiting** 3대 요건을 만족해야 한다. 해결법은 4층으로 분류 — **SW**(Dekker·Peterson·Dijkstra·Lamport 등)는 유연하지만 복잡·busy waiting 취약, **HW**(TestAndSet 기계어)는 atomic·단순하지만 busy waiting, **OS 지원 SW**(Spinlock·**Semaphore**·Eventcount/Sequencer)는 busy waiting 문제를 해결, **언어 레벨**(**Monitor**)은 OO 유사 구성체로 쉬운 사용을 제공한다. Semaphore/Monitor는 ME뿐 아니라 동기화·Producer-Consumer·Reader-Writer·Dining Philosopher 등 고전 문제를 해결한다.

## 핵심 포인트

### 1. 배경 & 용어

- **Process synchronization**: 프로세스들이 **동작을 맞추고 정보를 공유**.
- **Asynchronous (비동기)**: 프로세스들이 서로 모름.
- **Concurrent (병행)**: 여러 프로세스가 시스템에 공존.
- **비동기 + 병행 + 공유 자원 접근** → 문제(race) 발생.

| 용어 | 의미 |
|---|---|
| **Shared data / Critical data** | 여러 프로세스가 공유하는 데이터 |
| **Critical section (CS, 임계 영역)** | 공유 데이터를 접근하는 코드 영역 |
| **Mutual exclusion (상호배제, ME)** | 둘 이상의 프로세스가 동시에 CS에 진입하는 것을 방지 |

### 2. Race condition 예제

`sdata ← sdata + 1`은 3개 기계어(`Load`·`Add`·`Store`)로 구성. 기계어는 atomic(indivisible)이나 **상위 연산 전체는 아님**. 두 프로세스의 명령어가 인터리빙되면 최종 결과가 달라진다 (예: 기대 2 vs 실제 1).

### 3. ME Primitives

- `enterCS(CSk)`: 진입 전 검사 (다른 프로세스 CS 내 존재 여부).
- `exitCS(CSk)`: 벗어날 때 후처리 (시스템에 알림).

### 4. ME 3대 요건

- **Mutual exclusion**: CS에 프로세스 있으면 타 진입 금지.
- **Progress (진행)**: CS 밖 프로세스가 타 진입을 방해하면 안 됨.
- **Bounded waiting (한정대기)**: CS 진입은 **유한시간 내 허용**.

### 5. Two-Process ME 진화 실패 사례

| 버전 | 구성 | 위배 조건 | 이유 |
|---|---|---|---|
| v1 | `turn` 변수 하나 | **Progress** | P0 미진입 시 P1 block. 한 프로세스 두 번 연속 CS 진입 불가. |
| v2 | `flag[0/1]` (먼저 while, 이후 true) | **Mutual exclusion** | 중간 preemption 시 둘 다 CS 진입 가능. |
| v3 | `flag[0/1]` (먼저 true, 이후 while) | **Bounded waiting** | 동시 flag=true → 상호 대기. |

### 6. ME 솔루션 4 분류

#### (a) SW Solutions

**Two-process**:
- **Dekker's algorithm**: 2-process ME 보장 **최초 알고리즘**. flag + turn 조합.
- **Peterson's algorithm**: Dekker보다 간단. 한 줄의 while 조건 `(flag[j] and turn=j)`.

**N-process**:
- **Dijkstra**: 최초로 N개 프로세스 ME를 SW로 해결. `flag` = idle / want-in / in-CS 3상태.
- **Knuth**: 패턴 반복 분석 → 무한정 연기 배제. 그러나 긴 대기.
- **Lamport**: **Bakery algorithm** (빵집 번호표) — 우선순위 기반.
- **Brinch Hansen**: 긴 실행 시간 프로세스 보완 → Monitor로 발전.

#### (b) HW Solution

**TestAndSet (TAS) instruction**:
- `TAS(target)` = 이전 값 반환 + target=true, **한 번에 (atomic·indivisible)**.
- 실행 중 interrupt 못 받음 (preemption 불가).
- N-process ME 구현 가능 (wait[] + lock).
- **단점**: Busy waiting, 3+프로세스 starvation.

#### (c) OS-Supported SW Solutions

**Spinlock**:
- 정수 변수 + 초기화·P()·V()만. Atomic (OS 지원).
- `P(S)`: while(S≤0); S←S−1. `V(S)`: S←S+1.
- 멀티프로세서 시스템만 사용 가능. **Busy waiting!**

**Semaphore** (1965, **Dijkstra** 제안):
- 음 아닌 정수형 S. 초기화·P·V로만 접근.
- `P(S)`: S>0이면 S−1, 아니면 **queue QS에 대기**(asleep).
- `V(S)`: QS에 대기자 있으면 wake-up, 없으면 S+1.
- **No busy waiting**. Wake-up 순서는 비결정적 → starvation 가능.
- 종류: **Binary** (0/1, ME·동기화) / **Counting** (≥0, P-C 등).
- Windows `CreateSemaphore`, System V IPC.

**Eventcount / Sequencer** (은행 번호표 비유):
- **Sequencer**: 정수 변수, 감소 없음. `ticket(S)` — 현재까지 호출 횟수 반환 + 증가.
- **Eventcount**: `read(E)`, `advance(E)` (E++, wake-up), `await(E, v)` (E<v면 대기).
- **No busy waiting + No starvation** (FIFO).
- Semaphore보다 **low-level control** 가능.

#### (d) Language-Level Solution

**Monitor**:
- **공유 데이터 + CS 집합**. OO와 유사.
- **Conditional variable**: `wait()`, `signal()`.
- **Mutual exclusion 자동** (모니터 내 1 프로세스만).
- **Information hiding**: 공유 데이터는 모니터 내부에서만 접근.
- 구조:
  - **Entry queue**: 모니터 내 procedure 수만큼.
  - **Condition queue**: 특정 이벤트 대기.
  - **Signaler queue**: signal() 호출자 임시 대기 (1개).
- 지원: Java `synchronized`, .NET `System.Threading.Monitor`.

### 7. Semaphore 활용 고전 문제

#### (a) ME
```
P(active);  // S=1 초기화. CS 진입.
[CS]
V(active);
```

#### (b) Process Synchronization
```
Pi: ... L_i: P(sync); ...   // Pj가 L_j 통과할 때까지 대기
Pj: ... L_j: V(sync); ...
```

#### (c) Producer-Consumer (single buffer)
- `consumed`(1), `produced`(0) 두 semaphore.
- Producer: `P(consumed); buffer←M; V(produced);`
- Consumer: `P(produced); m←buffer; V(consumed);`

#### (d) Producer-Consumer (N-buffer, circular)
- `n_full`(0), `n_empty`(N), `mutexP`(1), `mutexC`(1).

#### (e) Reader-Writer (reader preference)
- `wmutex`(1), `rmutex`(1), `nreaders`.
- 첫 reader가 P(wmutex), 마지막 reader가 V(wmutex). Writer는 독점.

### 8. Monitor 활용 고전 문제

- **자원 할당**: `R_Available` + `R_Free` 조건 변수.
- **Producer-Consumer (circular)**: `validBufs`, `in`, `out`, `bufHasData`, `bufHasSpace`.
- **Reader-Writer**: `numReaders`, `writing` + `readingAllowed`, `writingAllowed` 조건 큐. `queue()`로 대기 여부 검사.
- **Dining Philosopher** (5명, 포크 공유): 철학자별 `numForks[]`·`ready[]` 조건 큐. `pickup(i)`에서 좌우 포크 2개 확보, `putdown(i)`에서 양쪽 signal.

### 9. 분류 축 요약

```
Low-level mechanisms ─────────> High-level mechanisms
├─ SW (Dekker·Peterson·...)      └─ Language (Monitor)
├─ HW (TAS)                         · 사용 쉬움, error 적음
└─ OS-supported SW                  · 컴파일러·OS 지원 필요
   (Spinlock, Semaphore,
    Eventcount/Sequencer)
Flexible but Error-prone        Easy but Language-dependent
```

## 언급된 인물 (지연 생성)

이 장에서 인물 다수 언급되지만 후속 맥락에 따라 필요 시 페이지 생성:

- **Dijkstra (다익스트라)**: **Semaphore 1965** 제안자. N-process ME 최초 SW 해결.

- **Dekker**: 2-process ME 최초 알고리즘.
- **Knuth**: 패턴 반복 분석.
- **Lamport (램포트)**: Bakery algorithm.
- **Brinch Hansen**: 긴 실행 시간 보완 → Monitor 발전에 기여.
- **Hoare** (본 슬라이드 미명시이나 Monitor 창안자): 모니터 개념 도입.
