# DB 1주차 — 데이터베이스 개념 & DBMS

DB 강의 (2026 봄학기)의 1주차. 두 강의로 구성: ① 데이터베이스의 개념(기초 이론), ② 데이터베이스 관리 시스템(정의·기능·역사). 강의일 2026-03-02.

## 강의 1 — 데이터베이스의 개념

### 1. 데이터와 정보

- **데이터**: 관찰·측정된 사실(Fact) 또는 값(Value).
- **정보**: 데이터를 특정 목적으로 해석·가공한 형태. 의사결정에 사용.
- **정보 처리**: 데이터 → (컴퓨터 시스템) → 정보. 정확성·현재성이 핵심.

### 2. 정보 처리 방식

| 축 | 방식 | 특징 |
|---|---|---|
| 시점 | **배치(Batch)** | 모아서 일괄 처리. 효율적이나 대기 필요. 고지서·이자 계산. |
|  | **온라인(Online)** | 즉시 처리·응답. 사용자 중심. 실시간 조회. |
| 위치 | **중앙집중** | 한 곳에 모음. 통제·보안 효율. 피해 시 규모 큼. |
|  | **분산(Distributed)** | 발생 위치별로 분산. Globalization 대응. 부분 장애에 강함. |

### 3. 정보 시스템 유형

- **MIS** (Management Information System): 기획·운용·통제 지원.
- **DSS** (Decision Support System): 복합적 의사결정 지원. 데이터 웨어하우스·데이터 마이닝 연계.
- **CRM** (Customer Relationship Management): 고객 중심 분석·마케팅.
- **ERP** (Enterprise Resource Planning): 생산·물류·재무·회계·영업 통합.
- **제어 시스템** / **내장 시스템(Embedded)**: 실시간 제어 중심.

### 4. 데이터베이스 정의와 특징

[[데이터베이스]]는 한 조직의 여러 응용이 공동 사용하기 위해 통합 저장한 **운영 데이터의 집합**.

**4가지 성격**
- **공용(Shared)** — 여러 사용자·부서가 공유.
- **통합(Integrated)** — 중복 최소화, 통제된 중복.
- **저장(Stored)** — 컴퓨터가 접근 가능한 저장 매체에 있음.
- **운영(Operational)** — 조직 운영에 필수적인 데이터.

**동작 특징**: 실시간 접근성 · 계속적 변화 · 내용에 의한 참조(값으로 검색) · 동시 공용.

### 5. 파일 시스템 vs 데이터베이스

파일 시스템의 한계:
- 데이터 **중복**과 **비일관성(Inconsistency)**
- 데이터 **고립**
- **무결성(Integrity)** 제약 유지 어려움
- **원자성**(트랜잭션) 보장 어려움
- 동시 접근 충돌
- 보안 유지 어려움
- **데이터 종속성**(파일 구조 변경 → 응용 재작성)

DB의 장점: 중복 최소화, 일관성, 공용, 무결성, 보안, 표준화, 전체 데이터 요구의 파악·조정.
DB의 단점: 운영비 오버헤드, 자료처리 복잡성, 백업·회복 어려움, 시스템 취약성.

## 강의 2 — 데이터베이스 관리 시스템 (DBMS)

### 1. DBMS 정의

[[DBMS]]는 데이터베이스와 응용 프로그램 사이의 **중계자**. 모든 사용자와 응용이 DB를 공유할 수 있게 해주는 범용 소프트웨어 시스템.

### 2. DBMS 3대 기능

| 기능 | 언어 | 예시 명령 |
|---|---|---|
| 데이터 **정의** | DDL | `CREATE`, `ALTER`, `DROP` |
| 데이터 **조작** | DML | `INSERT`, `DELETE`, `UPDATE`, `SELECT` |
| 데이터 **제어** | DCL | `GRANT`, `REVOKE`, `COMMIT`, `ROLLBACK` |

제어 기능은 **일관성·무결성·보안**을 유지 — 백업/회복(Recovery), 인증(Authorization), 병행 제어(Concurrency Control) 포함.

### 3. 논리적 vs 물리적 구조, 그리고 데이터 독립성

- **논리적 구조**: 사용자가 생각하는 데이터의 가상 구조.
- **물리적 구조**: 저장 장치 위에 실제 저장된 구조.
- 두 구조는 **매핑(Mapping)** 관계로 연결.
- **[[데이터 독립성]]** — DBMS의 궁극 목적.
  - **논리적 독립성**: 논리 구조 변경 → 응용 영향 없음.
  - **물리적 독립성**: 저장 장치/인덱스 변경(디스크→SSD 등) → 응용 영향 없음.

### 4. 3단계 스키마

[[3단계 스키마]] = 외부 · 개념 · 내부.

| 단계 | 관점 |
|---|---|
| **외부 스키마** (Subschema) | 사용자·응용 관점 — 전체의 일부분 |
| **개념 스키마** (Schema) | 범조직 관점 — 모든 외부 스키마의 통합 |
| **내부 스키마** | 저장장치 관점 — 물리적 저장 구조 |

**데이터 사전(Data Dictionary)** 은 스키마 정보를 저장하는 시스템 DB. 그 안의 "데이터에 관한 데이터"가 **메타 데이터**.

### 5. 언어 계층

기계어 → 어셈블리 → **절차적**(What+How, C) → **객체지향**(C++, Java) → **비절차적**(SQL: What만).

DB 언어(SQL)는 비절차적, 시스템이 How를 알아서 처리.

### 6. 사용자 유형

- **일반 사용자** — 비절차적 DML로 접근.
- **응용 프로그래머** — 프로그램 언어 + DML로 DB 기반 응용 개발.
- **DBA** (Database Administrator) — DDL·DCL로 DB 정의·제어. 설계·운영·튜닝·백업/회복·권한 관리 총괄.

### 7. DBMS 역사

- **1960s 초** — [[Charles Bachman]] (GE), **네트워크 데이터 모델** 기반 최초 범용 DBMS.
- **1960s 말** — IBM의 **계층 데이터 모델** (IMS).
- **1970** — [[E.F. Codd]] *"A Relational Model for Large Shared Data Banks"* (CACM). [[관계형 데이터 모델]] 제안. 후에 ACM 튜링상.
- **1974** — IBM San Jose 연구소의 **System R** (최초 관계형 DBMS 프로토타입, **SQL** 최초 제안).
- **1978** — **[[Oracle]]** (SDL 회사, 최초 상업용 관계형 DBMS).
- **1980s** — DBMS가 하드웨어 독립적. 상용: Oracle, DB2, Ingres, Sybase, Informix. PC 기반: MS-Access, dBase, FoxPro.
- **2세대** — 객체지향 DBMS (이미지·비디오 등 복합 데이터).
- **3세대** — **객체 관계형 DBMS(ORDBMS)** — 현재 주류.
- **최근 동향** — 빅데이터 3V(Volume, Velocity, Variety), 데이터 마이닝, SNS, 분산 병렬 처리(Google MapReduce 2004, Apache Hadoop).
